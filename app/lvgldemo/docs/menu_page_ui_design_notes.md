# 菜单页面 UI 设计与实现笔记

> 本文档记录了功能菜单页面从手势方案到按钮方案的演进过程，以及关键的技术决策和经验总结。

---

## 一、设计背景

### 1.1 需求来源

主界面提供 6 个功能入口（语音对话 / 会议模式 / 图文智录 / 录音 / 媒体播放器 / 设置），需要一个统一的菜单页面承载这些入口，并支持以下交互：

- 点击菜单项进入对应功能页面
- 提供明确的"返回主界面"入口
- 支持上下滑动浏览所有菜单项（包括"设置"）
- 界面美观，无过大空白区域

### 1.2 设计约束

| 约束项 | 说明 |
|--------|------|
| 屏幕尺寸 | 320 × 240（参考 `SCREEN_HEIGHT = 320`） |
| 字体大小 | 28px（用户认可的大小，保持不变） |
| 按钮高度 | 50px（用户认可的高度，保持不变） |
| 按钮宽度 | `lv_pct(80)`（保持不变） |
| 按钮间距 | 4px（紧凑布局） |
| 标题栏高度 | 48px（含 ← 返回按钮和"功能菜单"文字） |
| 底部留白 | 5px（避免完全填满导致无法滚动） |

## 二、方案演进历程

### 2.1 第一版：纯手势方案（已废弃）

**设计**：
- 滚动方向：`LV_DIR_VER`（双向滚动）
- 手势回调：上滑/下滑/右滑都触发 `menu_back_to_main()`
- 添加 `LV_OBJ_FLAG_GESTURE_BUBBLE` 让手势冒泡

**问题**：
- ❌ LVGL 的手势识别机制不是基于速度，而是**滚动方向匹配优先**
- 双向滚动时，上滑和下滑都会被 scroll_cont 当作滚动消费
- 只有右滑能触发手势返回

**教训**：LVGL 中**滚动和手势无法同时响应同一方向**，方向匹配时滚动优先。

---

### 2.2 第二版：限制滚动方向 + 单向手势（已废弃）

**设计**：
- 滚动方向：`LV_DIR_TOP`（只允许向上滚动查看下方）
- 手势回调：下滑 + 右滑触发返回

**问题**：
- ❌ 用户反馈"无法滑动到设置"
- ❌ 用户无法向下回看已浏览的内容
- 用户体验差，不符合直觉

**教训**：限制滚动方向虽然能解决冲突，但牺牲了滚动自由度。

---

### 2.3 第三版：最终方案 - 第一行按钮返回（当前版本）✅

**设计**：
- 在菜单项列表第一行新增"返回主界面"按钮（图标 🏠）
- 完全移除手势回调代码
- 恢复 `LV_DIR_VER` 双向滚动
- 标题栏 ← 按钮保留（双重返回入口）
- 底部留白 5px（避免完全填满导致无法滚动）

**布局**：
```
┌───────────────────────┐
│ ←    功能菜单  (48px)  │  标题栏
├───────────────────────┤
│ [🏠] 返回主界面       │  ← 第一行（点击返回）
│ [📞] 语音对话         │
│ [📋] 会议模式         │
│ [📷] 图文智录         │  滚动容器 267px
│ [🎙️] 录音            │
│ [▶️] 媒体播放器       │
│ [⚙️] 设置            │
├───────────────────────┤
│ (空白 5px)             │
└───────────────────────┘
```

**优势**：
- ✅ 滚动完全自由，双向都能滑动
- ✅ 返回入口明确，用户无需学习手势
- ✅ 与其他列表式 UI 一致，符合用户习惯
- ✅ 标题栏 ← 按钮保留，双重返回入口
- ✅ 无手势冲突，代码简洁

## 三、关键技术细节

### 3.1 关键代码片段

#### 布局参数定义

```c
#define MENU_BTN_HEIGHT     50      /* 按钮高度 */
#define MENU_BTN_GAP        4       /* 按钮间距 */
#define MENU_START_Y        5       /* 在滚动容器内的起始位置 */
#define MENU_TITLE_HEIGHT   48      /* 顶部标题栏高度 */
#define MENU_SCROLL_TOP    MENU_TITLE_HEIGHT  /* 滚动容器起始 Y */
#define MENU_BOTTOM_MARGIN  5       /* 底部留白5px避免完全填满导致无法滚动 */
#define SCREEN_HEIGHT       320     /* 屏幕高度常量 */
```

#### 父屏幕滚动标志清除（关键！）

```c
/* 必须同时清除三个滚动标志，参考 wifi_page.c 和 ai_page.c 的成功做法 */
lv_obj_clear_flag(parent, LV_OBJ_FLAG_SCROLLABLE);
lv_obj_clear_flag(parent, LV_OBJ_FLAG_SCROLL_ELASTIC);   /* 关键！ */
lv_obj_clear_flag(parent, LV_OBJ_FLAG_SCROLL_MOMENTUM);  /* 关键！ */
```

**说明**：`lv_obj_create(NULL)` 创建的屏幕默认启用三个滚动标志。只清 `SCROLLABLE` 不够，`ELASTIC` 和 `MOMENTUM` 会让 LVGL 仍把手势当滚动处理，导致手势事件无法触发。

#### 滚动容器配置

```c
lv_obj_t *scroll_cont = lv_obj_create(parent);
lv_obj_remove_style_all(scroll_cont);
/* 高度 = 屏幕高 - 标题栏 - 底部留白 */
lv_obj_set_size(scroll_cont, lv_pct(100),
                SCREEN_HEIGHT - MENU_TITLE_HEIGHT - MENU_BOTTOM_MARGIN);
lv_obj_set_pos(scroll_cont, 0, MENU_SCROLL_TOP);
lv_obj_set_style_pad_all(scroll_cont, 0, 0);
lv_obj_set_scroll_dir(scroll_cont, LV_DIR_VER);              /* 双向滚动 */
lv_obj_set_scrollbar_mode(scroll_cont, LV_SCROLLBAR_MODE_OFF);
lv_obj_clear_flag(scroll_cont, LV_OBJ_FLAG_CLICKABLE);     /* 避免拦截按钮点击 */
```

#### 菜单项列表（7项）

```c
create_menu_item(scroll_cont, 0, LV_SYMBOL_HOME,     "返回主界面", btn_home_cb);
create_menu_item(scroll_cont, 1, LV_SYMBOL_CALL,     "语音对话",   btn_ai_cb);
```

#### 新增的 btn_home_cb 回调

```c
static void btn_home_cb(lv_event_t *e)
{
    LV_UNUSED(e);
    menu_back_to_main();
}
```

#### menu_back_to_main 实现

```c
static void menu_back_to_main(void)
{
    if (main_screen) {
        lv_scr_load_anim(main_screen, LV_SCR_LOAD_ANIM_MOVE_BOTTOM, 300, 0, false);
    }
}
```

## 五、关键经验总结

### 5.1 LVGL 手势与滚动冲突的本质

**核心结论**：LVGL 的手势识别机制**不是基于速度**，而是**滚动方向匹配优先**。

**详细机制**：
1. 用户按下并移动
2. LVGL 检查触摸点的对象是否可滚动 + 滚动方向是否匹配
3. 如果匹配 → **直接消费事件作为滚动**，不触发手势
4. 如果不匹配 → 才触发 `LV_EVENT_GESTURE`

**推论**：
- 双向滚动（`LV_DIR_VER`）时，上滑和下滑都会被消费，只有右滑能触发手势
- 限制滚动方向（如 `LV_DIR_TOP`）能让某一方向的手势生效，但牺牲滚动自由度

### 5.2 解决方案选择

| 方案 | 滚动能力 | 手势返回 | 复杂度 | 用户体验 | 推荐 |
|------|---------|---------|--------|---------|------|
| 纯手势 | 双向 | 仅右滑 | 简单 | 差 | ❌ |
| 限制滚动方向 | 单向 | 双向 | 简单 | 中 | ⚠️ |
| **第一行按钮返回** | **双向** | **无手势** | **简单** | **好** | **✅** |
| 复杂事件判断 | 双向 | 双向 | 复杂 | 中 | ❌ |

**最佳实践**：在需要滚动 + 返回的页面中，**优先使用按钮返回**，而非手势返回。

### 5.3 滚动标志清除的必要性

`lv_obj_create(NULL)` 创建的屏幕默认启用三个滚动标志：
- `LV_OBJ_FLAG_SCROLLABLE` - 可滚动
- `LV_OBJ_FLAG_SCROLL_ELASTIC` - 弹性效果（到边界还能拉）
- `LV_OBJ_FLAG_SCROLL_MOMENTUM` - 惯性滑动（松手后继续滑）

**必须同时清除三个**，否则 ELASTIC 和 MOMENTUM 会让 LVGL 仍把手势当滚动处理，从而拦截手势事件。

**参考成功案例**：
- `wifi_page.c` 第 853-856 行
- `ai_page.c` 第 1019-1022 行

### 5.4 底部留白的重要性

**问题**：滚动容器完全填满屏幕会导致最后一项贴边时无法滚动。

**原因**：LVGL 判断是否可滚动时，需要内容超过容器边界。如果容器完全填满，最后一项贴边时 LVGL 可能无法识别可滚动区域。

**解决方案**：底部留 5-20px 空白，让 LVGL 识别可滚动区域。

**经验值**：
- 5px：覆盖率 83%，几乎无空白感 ✅（当前选择）
- 10px：覆盖率 82%，微弱空白感
- 20px：覆盖率 79%，有明显空白感
- 0px：覆盖率 85%，但可能影响滚动
