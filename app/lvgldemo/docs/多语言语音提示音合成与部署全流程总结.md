## 1. 功能概述与原理

### 1.1 提示音机制：预录 WAV 与实时 TTS 是两套独立链路

设备上存在两套完全独立的语音链路，**不要混淆**：

| 链路 | 机制 | 音色 | 本教程范围 |
|------|------|------|-----------|
| **本地提示音** | 预录 WAV 文件，事件触发即播，不联网 | 微软神经音色（Nanami/Katja/Denise/Svetlana 等） | ✅ 是 |
| AI 对话语音 | 云端 TTS 实时合成（DashScope qwen-tts-realtime） | Cherry / Serena | ❌ 否（见关联文档 13.3） |

提示音选择预录方案的原因：唤醒、WiFi 断开等场景对**零延迟**要求高，且设备可能恰好处于断网状态（"WiFi 已断开"提示若依赖云端 TTS 将无法播出），本地 WAV 是唯一可靠路径。

### 1.2 播放链路与代码挂点

```
事件触发（唤醒成功 / WiFi 状态变化 / 静默超时）
    │
    ▼
wakeup_detector_play_prompt( i18n_get_prompt(PROMPT_xxx) )
    │                          │
    │                          └─ 播放时实时查 s_prompts[当前语言][场景]
    │                             → 切换语言后立即播对应语言音频，无需重启
    ▼
读取 /emmc/xiaoqxiaoq/*.wav → 音频解码播放
```

关键特性：**播放时实时查表**。`s_prompts` 是编译期二维表（存 rodata），语言维度在运行时由 `i18n_get_lang()` 决定，因此同一事件在不同语言模式下播放不同文件，切换即时生效。

### 1.3 任务规模

**5 个场景 × 6 种语言 = 30 条音频**。其中中英 10 条为同事遗留现役文件，本次新增日/德/法/俄 20 条。

## 2. 音频格式规范

### 2.1 设备要求

| 参数 | 值 |
|------|-----|
| 容器 | WAV（PCM 编码） |
| 采样率 | **16000 Hz** |
| 位深 | **16 bit** |
| 声道 | **单声道（mono）** |

### 2.2 格式校准方法（新项目必做）

不要凭记忆写参数，**以现役文件为准**：拉取一条设备上正在使用的 WAV，用 ffprobe 核对：

```powershell
adb pull /emmc/xiaoqxiaoq/hello_go_ahead.wav .
ffprobe -hide_banner hello_go_ahead.wav
```

输出中确认 `16000 Hz, mono, s16`。所有新生成音频严格对齐此格式，否则设备端解码播放会异常（变速/静音/杂音）。

| PROMPT_QING_LIANJIE_WIFI | 未连网提示 | connect_to_wifi_please* | qinglianjiewifi.wav | connect_to_wifi_please.wav | Wi-Fiに接続してください |

| PROMPT_SILENCE_TIMEOUT | 静默超时退出 | no_problem_ill_step_back* | meiyouwentiwoxianxiale.wav | no_problem_ill_step_back.wav | ご用がなければ、失礼いたします |

新增四语的唤醒文案（与 UI 气泡 `STR_AI_WAKEWORD_REPLY` 一致，已验证）：

| 语言 | 唤醒成功文案 |
|------|-------------|
| 日语 | こんにちは、どうぞ |
| 德语 | Hallo, ich höre zu! |
| 法语 | Bonjour, je vous écoute ! |
| 俄语 | Здравствуйте, я вас слушаю! |

其余四条场景文案按同表语义（请连接 Wi-Fi / Wi-Fi 已连接 / Wi-Fi 已断开 / 没有问题我先退下了）翻译即可。**重合成时注意各语言专有词写法**（从 i18n 字符串表已定稿译文提取最保险）：德语用 WLAN/Wi-Fi、法语用带连字符的 Wi-Fi、俄语录音机是 Диктофон（勿直译）。

**命名规则**：文件名 = 英文基名 + 语言后缀（`_ja` / `_de` / `_fr` / `_ru`），中英文沿用历史无后缀名。文件名即代码中 `s_prompts` 表的键，**先定名后合成**，避免二次返工。

## 5. 语音合成

### 5.1 三条路径对比与选型结论

| 路径 | 成本 | 输出格式 | 适用 | 实测结论 |
|------|------|---------|------|---------|
| **A. edge-tts（主路径，推荐）** | 完全免费、无额度限制 | MP3（需转码） | 本项目 20 条 | ✅ 实际采用 |
| B. 百炼控制台 qwen3-tts-flash | 按量计费（与文本模型额度**独立计量**） | 在线播放/下载（URL 24h 有效） | 少量试听 | 账号 TTS 额度不可用时受阻 |
| C. dashscope Python SDK | 按量计费 | **可直出 16kHz WAV 免转码** | 批量可复现 | 额度可用时优于 A |

**选型逻辑**：路径 B/C 音色为 Cherry 系（与 AI 对话同源），路径 A 为微软神经音色——音色不同源但完全可接受（提示音与 AI 对话本就是两个功能）。额度是第一决定因素，20 条短文案约 300 字符，免费路径完全够用。

### 5.2 主路径：edge-tts 命令模板

音色表（四语均为高质量女声）：

| 语言 | 音色参数 |
|------|---------|
| 日语 | `ja-JP-NanamiNeural` |
| 德语 | `de-DE-KatjaNeural` |
| 法语 | `fr-FR-DeniseNeural` |
| 俄语 | `ru-RU-SvetlanaNeural` |

命令模板（每条音频一行，替换文本与输出名即可）：

```powershell
edge-tts --voice ja-JP-NanamiNeural --text "こんにちは、どうぞ" --write-media hello_go_ahead_ja.mp3
edge-tts --voice de-DE-KatjaNeural  --text "Hallo, ich höre zu!" --write-media hello_go_ahead_de.mp3
edge-tts --voice fr-FR-DeniseNeural --text "Bonjour, je vous écoute !" --write-media hello_go_ahead_fr.mp3
edge-tts --voice ru-RU-SvetlanaNeural --text "Здравствуйте, я вас слушаю!" --write-media hello_go_ahead_ru.mp3
```

统一存放到本地工作目录（如桌面 `voice` 文件夹）。完成后自查：**20 个 MP3（4 语言 × 5 条），双击抽查 2 条试听确认发音正确**。

> edge-tts 默认只能输出 MP3，无法直接生成 WAV，因此必须经过第 6 章转码。

### 5.3 备选路径 B：百炼控制台在线合成

1. 百炼控制台 → 模型广场 → `qwen3-tts-flash` → 模型详情页「在线体验」区（非独立页面）
2. 参数：音色 Cherry（设备运行时 TTS 同款，官方支持日/德/法/俄）；`language_type` 显式指定语种（Chinese/English/German/French/Russian/Japanese 等 10 种）——**显式指定比自动检测发音更准**
3. **合成后当场下载**：体验区返回的音频 URL 有效期仅 24 小时

> 踩坑提示：控制台点合成报"模型调用出错"时，先跑一次默认示例排除参数问题；默认示例也报错则是账号未开通该模型或 TTS 额度耗尽（TTS 与文本模型额度相互独立，文本模型有余额不代表 TTS 可用）。

### 5.4 备选路径 C：dashscope SDK 批量直出

```python
from dashscope.audio.tts_v2 import SpeechSynthesizer, AudioFormat

synth = SpeechSynthesizer(
    model="qwen3-tts-flash",
    voice="<目标音色>",
    format=AudioFormat.WAV_16000HZ_MONO_16BIT,  # 直出设备格式，跳过转码
)
synth.call("<文案>")
```

适用额度充足、需要可复现批量生产的场景。

## 6. 格式转码（MP3 → 设备格式 WAV）

### 6.1 FFmpeg 获取：pip 方案（公司网络受阻时的最优解）

三种获取方式按实测推荐排序：

| 方式 | 命令 | 实测结论 |
|------|------|---------|
| **① pip imageio-ffmpeg（推荐）** | `pip install imageio-ffmpeg -i https://pypi.tuna.tsinghua.edu.cn/simple` | ✅ 走国内镜像秒装，免下载免配环境变量 |
| ② 手动下载便携版 | 官网下载 `ffmpeg-release-essentials.zip` 解压，用完整绝对路径调用 | 公司网慢时下载易卡死 |
| ③ winget 安装 | `winget install ffmpeg` | ❌ 本机报"系统无法执行指定的程序" |

pip 方案的额外优势：**绕开公司电脑配环境变量的权限限制**——不解压、不配 PATH，通过 Python 命令直接拿到 ffmpeg 可执行文件的完整路径。

### 6.2 批量转码脚本（绝对路径版，可直接照抄）

```powershell
# ===== 变量区（按实际路径修改） =====
$src  = "C:\Users\<用户名>\Desktop\voice"        # MP3 源目录（绝对路径）
$dst  = "C:\Users\<用户名>\Desktop\wav_out"      # WAV 输出目录（绝对路径）
$ff   = python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"
# 若 python 命令不存在，改用： $ff = py -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"

# ===== 创建输出目录（已存在则跳过，不报错） =====
New-Item -ItemType Directory -Force -Path $dst | Out-Null

# ===== 批量转码：16kHz / 单声道 / 16bit =====
Get-ChildItem "$src\*.mp3" | ForEach-Object {
    & $ff -y -i $_.FullName -ar 16000 -ac 1 -sample_fmt s16 (Join-Path $dst ($_.BaseName + ".wav"))
}
```

**为什么必须绝对路径**：曾用相对路径 `..\wav_out` 导致"输出目录不存在"报错——`mkdir` 的执行位置与后续转换命令的工作目录不一致（见 10.3 坑例）。绝对路径完全消除对终端当前目录的依赖，一次写对。

### 6.3 结果自查

```powershell
(Get-ChildItem "$dst\*.wav").Count    # 应输出 20
```

- 数量 = 20（4 语言 × 5 条）
- 双击抽查 2 条可正常播放
- 可选：`ffprobe` 抽查一条确认 `16000 Hz, mono, s16`

## 7. 设备部署（adb 推送）

### 7.1 前置：确认目标目录存在

```powershell
adb shell mkdir -p /emmc/xiaoqxiaoq
adb shell df /emmc      # 顺带确认分区空间充足
```

> eMMC 分区下目录不存在时直接推送必失败；`-p` 幂等创建，目录已存在也不报错。

### 7.2 逐文件推送（规避 error 22 的正确姿势）

```powershell
$dst = "C:\Users\<用户名>\Desktop\wav_out"
Get-ChildItem "$dst\*.wav" | ForEach-Object {
    adb push $_.FullName "/emmc/xiaoqxiaoq/$($_.Name)"
}
```

**关键：必须逐文件、目标写完整绝对路径**。曾尝试 `adb push wav_out\. /emmc/xiaoqxiaoq/` 的通配符目录写法，触发 `adb: error: failed to read copy response` + 设备端 `remote Unknown error 22`（设备 adbd 拒收带 `.` 的相对路径写法）。逐文件循环推送一次通过。

### 7.3 设备端核对

```powershell
adb shell ls /emmc/xiaoqxiaoq/    # 应看到全部 30 条 wav（含历史中英文 10 条）
```

## 8. 固件接入（i18n.c s_prompts 表）

### 8.1 表结构

```c
static const char *const s_prompts[LANG_COUNT][PROMPT_COUNT] = {
    [LANG_ZH_CN] = { /* 指向 /emmc/xiaoqxiaoq/ 无后缀历史文件 */ },
    [LANG_EN]    = { /* 指向无后缀历史文件 */ },
    [LANG_JA]    = { /* 指向 *_ja.wav */ },
    [LANG_DE]    = { /* 指向 *_de.wav */ },
    [LANG_FR]    = { /* 指向 *_fr.wav */ },
    [LANG_RU]    = { /* 指向 *_ru.wav */ },
};
```

新增语言的修改模式：

- **LANG_JA 行**：原本过渡期指向英文 wav，5 条全部改为 `_ja` 后缀文件
- **LANG_DE/FR/RU 行**：原本为 NULL（C designated initializer 缺省置 NULL，回落机制自动播英文），填充 `_de/_fr/_ru` 后缀文件名

同步修改需在**堡垒机**代码树进行（与本地 diff 逐一核对后编译）。

### 8.2 部署顺序（不可颠倒）

```
① adb 推送全部 wav → ls 确认在位
② 修改 s_prompts 指向新文件
③ 编译烧录固件
④ 按第 9 章清单验证
```

若先烧固件后推音频，存在**窗口期**：新模式播放提示音 `open failed`（表现为静音，不崩溃）。先推音频则无此问题。

## 10. 踩坑实录

| # | 现象 | 根因 | 解法 |
|---|------|------|------|
| 1 | winget 装 FFmpeg 报"系统无法执行指定的程序" | 公司电脑 winget 执行受限 | 改用 `pip install imageio-ffmpeg`，Python 取路径 |
| 2 | `$ff` 报"不是可识别的命令" | 在 **cmd** 窗口跑了 PowerShell 专属语法 | 看提示符：无 `PS` 前缀即 cmd；换 VS Code 内置 PowerShell 终端 |
| 3 | 转码报"输出目录不存在"，wav_out 为空 | 相对路径 `..\wav_out` 依赖终端当前目录，mkdir 与转换执行位置不一致 | 源、目标全用绝对路径 + `New-Item -Force` |
| 4 | 转换后 wav_out 仍为空 | 命令工作目录不在 MP3 所在的 voice 目录 | 脚本内显式 `$src` 绝对路径，不再依赖 cd |
| 5 | `adb push wav_out\. /emmc/...` 报 `remote Unknown error 22` / `failed to read copy response` | 设备 adbd 拒收带 `.` 的通配符相对路径写法 | PowerShell 循环逐文件推送，目标写完整绝对路径 |
| 6 | 推送直接失败（非 error 22） | 设备 `/emmc/xiaoqxiaoq` 目录不存在 | 先 `adb shell mkdir -p /emmc/xiaoqxiaoq` |
| 7 | 百炼控制台点合成报"模型调用出错" | 账号未开通 qwen3-tts-flash 或 TTS 额度耗尽（与文本模型额度独立计量） | 跑默认示例定位；不可用则切 edge-tts 免费路径 |
| 8 | 控制台合成音频隔天链接失效 | 在线体验区音频 URL 有效期仅 24 小时 | 合成后当场下载存本地 |
| 9 | 先烧固件后推音频，窗口期提示音静音 | 文件未在位，播放 open failed（不崩溃） | 部署顺序固化为：先推音频 → 后烧固件 |
| 10 | 播母语语音但气泡显英文 | 音频与文字两条独立链路，翻译未落位触发回落 | 属预期，补齐 i18n 字符串表条目 |

## 11. 经验总结与最佳实践

1. **格式以现役文件为准**：新音频参数永远从设备拉一条现役 wav 用 ffprobe 校准，不凭记忆写。
2. **先定文件名、再合成**：文件名是 s_prompts 表的键，文案可以改，命名规则先冻结。
3. **Windows 受限环境依赖获取优先级**：pip 镜像包 > 手动下载便携版 > winget/系统包管理器（权限受限最易失败）；pip 方案同时免去环境变量配置。
4. **PowerShell 脚本一律绝对路径**：公司电脑终端入口多（cmd/PS/VS Code），当前目录不可控，相对路径是最大变数。
5. **adb 批量推送逐文件循环**：目标写完整绝对路径，规避 adbd 对特殊路径写法的拒收；推送前先建目录、查空间。
6. **音频部署先于固件**：固化"推文件 → 改表 → 编译烧录 → 验证"顺序，消灭窗口期。
7. **额度独立计量意识**：百炼平台文本模型与 TTS 模型额度分开计费，一个有余额不代表另一个可用；控制台报错先跑默认示例区分"参数错"与"账号错"。
8. **双链路独立验证**：音频母语化与文字翻译是两条线，验收时分别确认"播对音"与"显对字"。
