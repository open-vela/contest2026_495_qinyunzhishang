## 1. 功能概述

### 1.1 功能定义

为 BES2800BP 开发板的 LVGL 界面提供多语言切换能力（现已支持中/英/日/德/法/俄六语），覆盖所有界面页面的文字与字体显示：

| 功能 | 说明 |
|------|------|
| 语言选择 | 「设置 → 语言」页面选择，确认后生效 |
| 持久化保存 | 配置写入 `/emmc/lang_config`，重启保持 |
| 即时切换 | 确认后无需重启，界面立即刷新为新语言 |
| 全页面覆盖 | 主页、菜单、设置、AI、会议、相机、录音、播放器等 |
| 字体适配 | 各语言加载适配字号的 FreeType 字体 |
| 状态拦截 | 通话/录音/会议进行中禁止切换，避免资源冲突 |

### 1.2 用户操作流程

```
┌─────────────────────────────────────────────────────────────────┐
│  主页（main_screen）                                            │
│    │ 上滑                                                       │
│    ▼                                                            │
│  菜单页（menu_screen）                                          │
│    │ 点击「设置」                                                │
│    ▼                                                            │
│  设置页（settings_screen）                                      │
│    │ 点击「语言」                                                │
│    ▼                                                            │
│  语言设置页（lang_screen）                                      │
│    ├─ 点击语言选项 → 仅更新圆点选中状态                          │
│    │ 点击「确认」                                                │
│    ├─ 未改变语言 → 提示"当前已是XX"                              │
│    ├─ 通话/录音/会议中 → 弹窗拦截                                │
│    └─ 语言改变 → 保存配置 + 提示"切换成功"                       │
│    │ 右滑返回                                                    │
│    ▼                                                            │

│    │ 右滑返回                                                    │

│  菜单页（重建，文字已刷新为新语言）                              │

└─────────────────────────────────────────────────────────────────┘
```

### 1.3 设计约束

| 约束 | 说明 |
|------|------|
| 内存受限 | NuttX RTOS 嵌入式环境，堆内存有限，不能频繁 malloc/free |
| FreeType 字体昂贵 | 单个字体加载占数十 KB，需复用而非重建 |
| LVGL 异步渲染 | 删除字体时若有 label 仍在引用，会触发 Usage Fault 死机 |
| 页面生命周期复杂 | 常驻页（主页）与非驻留页刷新策略不同 |

## 2. 整体架构设计

### 2.1 方案选型：方案 B + 局部方案 C

- **方案 B（集中式字符串表）**：所有界面文字集中在 i18n.c 的 `s_strings` 二维数组，全局变量 `g_current_lang` 记录当前语言，页面通过 `i18n_get(STR_xxx)` 查表获取。零冗余、易维护，但非驻留页切语言后需重建才刷新。
- **局部方案 C（语言变更回调）**：仅常驻页（主页）注册 `lang_changed_cb`，切换后原地刷新字体/文字，避免重建闪烁、节省内存。

### 2.2 系统分层架构

```
应用层：lang_dialog.c（语言页）/ xiaoq_page.c（主页·回调原地刷新）
        menu/settings/camera/ai/meeting/recorder/player 等（重建刷新）
i18n 核心层：i18n.c/h —— 字符串表 + 语言状态机 + 字体管理 + 回调广播
字体层：lv_freetype_font_create() 加载 MiSans-Normal.ttf
        s_cjk_font(28px 标题) / s_cjk_font_small(24px 正文)
持久化层：/emmc/lang_config（"zh"/"en"/"ja"/"de"/"fr"/"ru"）
```

核心切换数据流见第 7 章（唯一完整版）。

## 3. 核心模块：i18n 国际化模块

### 3.1 模块职责

`i18n.c` / `i18n.h` 是语言切换功能的核心：

| 能力 | 函数 | 说明 |
|------|------|------|
| 初始化 | `i18n_init()` | 开机调用，从文件读取语言配置，**必须在创建任何 UI 之前** |
| 获取字符串 | `i18n_get(STR_xxx)` | 查表返回当前语言文字 |
| 获取/设置语言 | `i18n_get_lang()` / `i18n_set_lang()` | 读取/切换当前语言 |
| 字体应用 | `i18n_apply_font()` / `i18n_apply_font_small()` | 给 label 应用 28px/24px 字体 |
| 字体获取 | `i18n_get_cjk_font()` / `i18n_get_cjk_font_small()` | 获取共享字体指针 |
| 回调注册 | `i18n_register_lang_cb()` | 常驻页注册语言变更回调 |
| 延迟广播 | `i18n_flush_lang_changed()` | 退出语言页时广播给常驻页 |
| 页面重建 | `i18n_rebuild_current_page()` | 销毁所有功能页，重建设置页 |

### 3.2 全局状态变量

```c
/* 当前语言（开机时从文件读取，默认中文） */
static lang_t g_current_lang = LANG_ZH_CN;

/* 共享的 FreeType 字体（28px，懒加载，用于标题） */
static lv_font_t *s_cjk_font = NULL;

/* 共享的 FreeType 字体（24px，懒加载，用于正文/UI提示） */
static lv_font_t *s_cjk_font_small = NULL;

/* 语言变更回调列表（主页等常驻页注册，最多4个回调） */
static lang_changed_cb s_lang_cbs[MAX_LANG_CBS];
static bool s_lang_pending = false;  /* 延迟广播标记 */
```

### 3.3 初始化流程

开机时在 lvgldemo.c 中调用 `i18n_init()`：

```
i18n_init()                           [i18n.c]
  │
  ├─ i18n_load_lang_from_file()
  │    ├─ open("/emmc/lang_config", O_RDONLY)
  │    ├─ 文件不存在 → 返回 LANG_ZH_CN（首次开机默认中文）
  │    ├─ read(fd, buf, 8)
  │    └─ 内容 "en"/"ja"/"de"/"fr"/"ru" → 对应语言，否则中文
  │
  ├─ g_current_lang = 读取结果
  ├─ syslog("[i18n] init, lang=xx")
  └─ 不预加载字体（懒加载，首次使用时才加载）
```

**关键设计：懒加载字体**

字体不在 `i18n_init()` 时加载，而是首次调用 `i18n_apply_font()` 或 `i18n_get_cjk_font()` 时才加载。原因：
1. 节省启动时间（FreeType 字体加载耗时约 100ms）
2. 节省内存（若用户从不切换语言，英文模式无需加载 CJK 字体）
3. 但实际上各语言模式都会加载（英文模式下语言页仍需显示"简体中文"）

## 4. 字符串表设计

### 4.1 字符串 ID 枚举

所有界面文字都定义在 i18n.h 的 `str_id_t` 枚举中，按页面分组：

```c
typedef enum {
    /* 主界面 */
    STR_HOME_DATE_FMT,          /* "%d月%d日" / "%b %d" 等，按语言表 */
    STR_HOME_WEEK_SUN,          /* 星期日 / Sun / 日 / So / Dim / Вс */
    ...

    /* 菜单页 */
    STR_MENU_AI,                /* 语音对话 / AI Assistant */
    STR_MENU_MEETING,           /* 会议模式 / Meeting */
    STR_MENU_CAMERA,            /* 图文智录 / AI Camera */
    ...

    /* 语言选择弹窗 */
    STR_LANG_DIALOG_TITLE,      /* 语言 / Language / 言語 ... */
    STR_LANG_SWITCH_OK,         /* 切换成功 / Switch success */
    ...

    STR_COUNT  /* 总数，用于数组边界检查 */
} str_id_t;
```

### 4.2 二维字符串表

字符串存储在 i18n.c 的 `s_strings[LANG_COUNT][STR_COUNT]` 二维数组中，**编译期确定，存放在 rodata 段**：

```c
static const char *const s_strings[LANG_COUNT][STR_COUNT] = {
    [LANG_ZH_CN] = {
        [STR_MENU_AI]      = "语音对话",
        [STR_MENU_MEETING] = "会议模式",
        [STR_MENU_CAMERA]  = "图文智录",
        ...
    },
    [LANG_EN] = {
        [STR_MENU_AI]      = "AI Assistant",
        [STR_MENU_MEETING] = "Meeting",
        [STR_MENU_CAMERA]  = "AI Camera",
        ...
    },
    /* [LANG_JA] / [LANG_DE] / [LANG_FR] / [LANG_RU] 同构，见 13/14/15 章 */
};
```

**设计要点**：
- 使用 C99 指定初始化器 `[STR_xxx] = "..."`，未赋值的项自动为 NULL（14.2 回落机制依赖此特性）
- `const` 修饰符确保字符串不可变，编译器可优化
- 二维数组结构使得 `i18n_get()` 只需一次数组索引：`s_strings[g_current_lang][id]`

### 4.3 字符串获取函数

```c
const char *i18n_get(str_id_t id)
{
    if (id < 0 || id >= STR_COUNT) {
        return "";
    }
    return s_strings[g_current_lang][id];
}
```

**使用示例**（各页面统一模式）：
```c
lv_label_set_text(title, i18n_get(STR_CAM_TITLE));      // 相机页标题
lv_label_set_text(btn, i18n_get(STR_MENU_SETTINGS));    // 菜单项
lv_label_set_text(status, i18n_get(STR_AI_LISTENING)); // AI状态
i18n_apply_font(title);                                 // 配套字体
```

（探针版起 NULL 自动回落英文，完整实现见 14.2）

### 4.4 特殊处理：日期格式

主页日期格式各语言差异较大，使用格式化字符串 + 运行时拼接（现共三类分支，详见 15.2）：

| 语言 | 格式来源 | 示例 |
|------|--------|------|
| 中文/日语 | 硬编码 `"%d月%d日"` | `7月21日` |
| 英文 | `"%s %d"` + 月份缩写表 | `Jul 21` |
| 德/法/俄 | 语言表 `STR_HOME_DATE_FMT`（参数序 日,月） | `21.10.` / `21/10` / `21.10` |

英文模式需额外用月份索引查 `i18n_en_months[12]` 表获取月份缩写：
```c
const char *const i18n_en_months[12] = {
    "Jan", "Feb", "Mar", "Apr", "May", "Jun",
    "Jul", "Aug", "Sep", "Oct", "Nov", "Dec"
};
```

实现见 xiaoq_page.c 的 `homepage_update_datetime()`。

## 5. 字体管理体系

### 5.1 字体资源

全部语言共用 `/emmc/font/MiSans-Normal.ttf`（含汉字/拉丁/西里尔/假名，见 14.8 覆盖结论），FreeType 按需渲染指定位图。

### 5.2 共享字体层级

```
┌──────────────────────────────────────────────────────────────┐
│  共享字体（i18n.c 管理，全局单例，懒加载）                    │

├──────────────────────────────────────────────────────────────┤
│  主页私有字体（xiaoq_page.c 管理）                            │
│                                                              │
│  time_font     ── 时钟数字（中文120px，英文100px）           │
```

### 5.3 字体应用函数

#### i18n_apply_font（28px 标题字号）

```c
void i18n_apply_font(lv_obj_t *obj)
{
    i18n_ensure_cjk_font();  // 懒加载
    if (s_cjk_font) {
        lv_obj_set_style_text_font(obj, s_cjk_font, 0);
        return;
    }
    /* CJK 字体加载失败：fallback 到 montserrat_24 */
    lv_obj_set_style_text_font(obj, &lv_font_montserrat_24, 0);
}
```

**各语言模式均使用 MiSans 28px**，原因：
1. MiSans 含拉丁字符，英文模式下同样可读
2. 保证字号一致，避免切换语言时布局跳动
3. 历史 Bug7：原英文模式回退到 montserrat_24（24px）偏小，已修复

#### i18n_apply_font_small（24px 正文字号）

```c
void i18n_apply_font_small(lv_obj_t *obj)
{
    if (g_current_lang != LANG_EN) {
        /* 非英文语言（中/日/德/法/俄）用 MiSans 24px：
         * montserrat 无西里尔/变音符字形（条件由"仅中文"改为
         * "非英文"，见 14.4），且回落英文条目亦需 MiSans 渲染 */
        i18n_ensure_cjk_font();
        if (s_cjk_font_small) {
            lv_obj_set_style_text_font(obj, s_cjk_font_small, 0);
            return;
        }
        /* 24px 加载失败则 fallback 到 28px */
        if (s_cjk_font) {
            lv_obj_set_style_text_font(obj, s_cjk_font, 0);
            return;
        }
    }
    /* 英文模式或字体都加载失败：用 montserrat_24 */
    lv_obj_set_style_text_font(obj, &lv_font_montserrat_24, 0);
}
```

**用途**：录音/播放器/WiFi 等界面的非标题文字（文件列表、计时、状态提示），避免 28px 过大导致挤压。

### 5.4 字体获取函数

```c
lv_font_t *i18n_get_cjk_font(void)         // 28px
{
    i18n_ensure_cjk_font();  /* 总是确保加载后返回 */
    return s_cjk_font;
}
lv_font_t *i18n_get_cjk_font_small(void)   // 24px，同理
```

**关键修复**：这两个函数**总是确保字体已加载并返回**，无论什么语言模式。

历史 Bug4：
- 之前英文模式返回 NULL → 选项文字 fallback 到 montserrat（不含中文）→ "简体中文"显示方框
- 切换语言后渲染访问空字体指针 → `lv_font_get_glyph_width` 崩溃
- 修复：始终调用 `i18n_ensure_cjk_font()` 后返回有效字体

### 6.3 页面入口函数

```c
void lang_page_enter(void)
{
    if (lang_screen || s_switching) return;  // 防重复进入

    s_selected_lang = i18n_get_lang();       // 初始化为当前语言
    s_language_changed = false;
```

### 7.2 i18n_set_lang 详解

```c
bool i18n_set_lang(lang_t lang)
{
    if (lang == g_current_lang) return true;  // 无变化

    /* 1. 写持久化文件 */
    int fd = open(LANG_CONFIG_FILE, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    const char *data = i18n_lang_code(lang);  /* "zh"/"en"/"ja"/... */
    write(fd, data, 2);
    close(fd);

    /* 2. 更新内存状态 */
    g_current_lang = lang;

    /* 3. 字体处理 */
    if (lang == LANG_ZH_CN) {
        i18n_ensure_cjk_font();  // 切中文：确保CJK字体已加载
    }
    /* 切英文：不立即释放CJK字体！
     * 原因：lang_screen 上的 label 仍在使用该字体，删除会导致死机 */

    /* 4. 不立即广播！设置延迟标记 */
    s_lang_pending = true;

    return true;
}
```

### 7.3 lang_exit_to_settings 详解

整个切换流程中最关键的函数，负责在用户右滑返回时重建所有需要刷新的页面：

```c
static void lang_exit_to_settings(void)
{
    bool need_rebuild = s_language_changed;
    s_language_changed = false;

    if (need_rebuild)
    {
        /* 1. 重建设置页 */
        settings_page_deinit();
        settings_screen = lv_obj_create(NULL);
        create_settings_page(settings_screen);  // 文字会用新语言

        /* 2. 重建菜单页 */
        if (menu_screen) menu_page_force_delete();
        menu_screen = lv_obj_create(NULL);
        create_menu_page(menu_screen);

        /* 3. 销毁功能页屏幕（下次进入时重建） */
        ai_page_deinit();
        meeting_page_deinit();
        camera_page_deinit();
        camera_screen = NULL;  // camera_page_deinit 无法置空全局指针，需手动

        lv_scr_load_anim(settings_screen, LV_SCR_LOAD_ANIM_MOVE_RIGHT, 300, 0, false);

        /* 4. 延迟广播：通知主页刷新 */
        i18n_flush_lang_changed();
    }
    else
    {
        /* 未变更语言：直接返回设置页
         * Bug1修复：settings_screen 可能已被卸载回调销毁，需重建 */
        if (settings_screen == NULL) {
            settings_screen = lv_obj_create(NULL);
            create_settings_page(settings_screen);
        }
        lv_scr_load_anim(settings_screen, LV_SCR_LOAD_ANIM_MOVE_RIGHT, 300, 0, false);
    }
}
```

## 8. 各页面的语言适配方式

### 8.1 页面分类

根据页面是否常驻，采用不同的语言刷新策略：

| 页面类型 | 页面 | 刷新策略 | 原因 |
|----------|------|----------|------|
| 常驻页 | main_screen（主页） | 回调原地刷新 | 避免重建闪烁，时钟不能中断 |
| 重建页 | menu_screen、settings_screen | 切换时立即重建 | 文字多，原地刷新复杂 |
| 按需重建页 | ai/meeting/camera/recorder/player | 销毁屏幕，下次进入重建 | 用户不一定使用，节省内存 |

### 8.2 主页（xiaoq_page.c）— 回调原地刷新

主页是常驻屏幕，注册了语言变更回调，切换语言时原地刷新字体和文字：

**注册回调**：
```c
i18n_register_lang_cb(homepage_lang_changed_cb);
```

**回调实现**：
```c
static void homepage_lang_changed_cb(lang_t lang)
{
    /* 1. 先把 label 字体设为安全值，避免悬空指针 */
    lv_obj_set_style_text_font(time_label, &lv_font_montserrat_24, 0);
    lv_obj_set_style_text_font(date_label, &lv_font_montserrat_24, 0);
    lv_obj_set_style_text_font(weekday_label, &lv_font_montserrat_24, 0);

    /* 2. 删除旧 FreeType 字体 */
    homepage_font_unload();

    /* 3. 按新语言加载新字体（中英文字号不同） */
    homepage_font_load(lang);

    /* 4. 应用新字体到 label */
    lv_obj_set_style_text_font(time_label, time_font, 0);
    lv_obj_set_style_text_font(date_label, date_font, 0);
    lv_obj_set_style_text_font(weekday_label, weekday_font, 0);

    /* 5. 刷新日期/星期文字（格式不同） */
    homepage_update_datetime();
}
```

**主页字体字号差异**：

| 元素 | 中文 | 英文 | 原因 |
|------|------|------|------|
| 时钟 | 120px | 100px | 英文数字较宽，缩小避免溢出 |
| 日期 | 39px | 48px | 英文"Jul 21"比"7月21日"短，字号调大更协调 |
| 星期 | 39px | 39px | 中英文都是短词，字号相同 |

### 8.3 菜单页（menu_page.c）— 重建刷新

菜单页没有注册语言回调，切换语言时通过 `menu_page_force_delete()` 删除后重建：

```c
void menu_page_force_delete(void)
{
    if (menu_time_timer) {
        lv_timer_del(menu_time_timer);
        menu_time_timer = NULL;
    }
    if (menu_screen) {
        lv_obj_del(menu_screen);
        menu_screen = NULL;
    }
    menu_time_label = NULL;
}
```

重建后，`create_menu_page()` 中的 `i18n_get(STR_MENU_xxx)` 会返回新语言的文字。

### 8.4 设置页（settings_page.c）— 重建刷新

设置页同理，通过 `settings_page_deinit()` 销毁后重建：

```c
void settings_page_deinit(void)
{
    if (settings_time_timer) {
        lv_timer_del(settings_time_timer);
        settings_time_timer = NULL;
    }
    settings_time_label = NULL;
    if (settings_screen) {
        lv_obj_del(settings_screen);
        settings_screen = NULL;
    }
}
```

### 8.5 功能页（ai/camera/meeting 等）— 按需重建

功能页在切换语言时只销毁屏幕对象（置空全局指针），不立即重建。下次从菜单进入时，`menu_enter_xxx()` 检测到 `xxx_screen == NULL` 会自动重建：

```c

{

        camera_screen = lv_obj_create(NULL);
        create_camera_page(camera_screen); // 用新语言重建
    }
    lv_scr_load_anim(camera_screen, LV_SCR_LOAD_ANIM_MOVE_RIGHT, 300, 0, false);
}
```

**各功能页 deinit 的 screen 置空情况**：

| 页面 | deinit 函数 | 是否置空全局 screen | 备注 |
|------|-------------|---------------------|------|
| ai_page | `ai_page_deinit()` | ✓ 置空 `ai_screen` | |
| meeting_page | `meeting_page_deinit()` | ✓ 置空 `meeting_screen` | |
| camera_page | `camera_page_deinit()` | ✗ 无法置空 `camera_screen` | 需手动 `camera_screen = NULL` |
| recorder_page | `recorder_page_deinit()` | ✓ | |
| player_page | `player_page_deinit()` | ✓ | |

**camera_page 的特殊处理**：`camera_page_deinit()` 只删除 `cam_screen_obj` 但无法置空全局 `camera_screen`（因为该变量定义在 lvgldemo.c 中），需要在 `lang_exit_to_settings()` 中手动置空（Bug5，见 11.5）。

## 9. 页面重建机制详解

### 9.1 屏幕生命周期管理

LVGL 的屏幕（`lv_obj_t *screen`）是顶级对象，切换屏幕用 `lv_scr_load_anim()`。本项目的屏幕管理采用**静态全局指针 + 懒创建**模式：

```c
/* 各页面的全局屏幕指针（定义在各自 .c 文件或 lvgldemo.c 中） */
lv_obj_t *main_screen     = NULL;  // 主页（常驻，开机创建）
lv_obj_t *menu_screen     = NULL;  // 菜单页
lv_obj_t *settings_screen = NULL;  // 设置页
lv_obj_t *camera_screen   = NULL;  // 相机页
lv_obj_t *ai_screen       = NULL;  // AI页
lv_obj_t *meeting_screen  = NULL;  // 会议页
/* ... */
```

### 9.2 进入页面的统一模式

所有功能页进入时都遵循「空则创建，非空则复用」模式：

```c
static void menu_enter_xxx_page(void)
{
    if (xxx_screen == NULL) {           // 首次进入或切语言后销毁
        xxx_screen = lv_obj_create(NULL);
        create_xxx_page(xxx_screen);    // 创建UI（使用i18n_get获取当前语言文字）
    }
    lv_scr_load_anim(xxx_screen, ...);  // 切换到该屏幕
}
```

### 9.3 屏幕卸载回调（SCREEN_UNLOADED）

部分页面注册了 `LV_EVENT_SCREEN_UNLOADED` 回调，在屏幕被切走后异步销毁：

```c
/* settings_page.c */
lv_obj_add_event_cb(parent, settings_screen_unloaded_cb,
                    LV_EVENT_SCREEN_UNLOADED, NULL);

static void settings_screen_unloaded_cb(lv_event_t *e)
{
    lvgl_dispatch_async(settings_deinit_async_cb, NULL);
}
```

**与语言切换的交互**：这导致了 Bug1（右滑返回失败），详见 11.1。

### 9.4 为什么不原地刷新所有页面？

| 方式 | 优点 | 缺点 |
|------|------|------|
| **原地刷新** | 无闪烁，省内存 | 需为每个 label 调用 `lv_label_set_text()`，页面多时代码冗长易漏 |
| **重建页面** | 代码简洁，自动刷新 | 有短暂闪烁，需正确销毁旧屏幕避免内存泄漏 |

本项目对功能页采用重建方式，因为：
1. 功能页文字较多（如相机页有标题、状态、按钮、提示等十余处）
2. 功能页用户不一定使用，重建开销可接受
3. 避免为每个页面维护繁琐的原地刷新逻辑

（例外：语言页自身的标题/确认按钮采用原地刷新，见 15.4——只两处控件，重建屏幕反而有崩溃风险）

## 10. 延迟广播机制（关键设计）

### 10.1 问题背景

最初的设计是 `i18n_set_lang()` 中同步广播语言变更事件，但导致了严重崩溃：

```
i18n_set_lang(EN)
  └─ 同步广播 → homepage_lang_changed_cb(EN)
       └─ homepage_font_unload()  // 删除旧字体
       └─ homepage_font_load(EN)  // 加载新字体
            └─ FreeType 字体重建过程中...
                 └─ LVGL 异步渲染访问已删除字体
                      └─ Instruction access violation (PC=0x00000000) 死机
```

**根因**：`lang_screen` 仍是活动屏幕时，LVGL 的异步渲染线程可能正在绘制使用旧字体的 label。同步删除字体会导致渲染线程访问已释放内存。

### 10.2 解决方案：延迟广播

将广播拆分为两步：

**第一步：设置标记（在 `i18n_set_lang` 中）**
```c
bool i18n_set_lang(lang_t lang)
{
    /* ... 写文件、更新状态 ... */
    s_lang_pending = true;  // 只设标记，不广播
    return true;
}
```

**第二步：延迟广播（在退出语言页时）**
```c
void i18n_flush_lang_changed(void)
{
    if (!s_lang_pending) return;
    s_lang_pending = false;

    lang_t lang = g_current_lang;
    for (int i = 0; i < MAX_LANG_CBS; i++) {
        if (s_lang_cbs[i]) {
            s_lang_cbs[i](lang);  // 调用主页回调
        }
    }
}
```

**调用时机**：在 `lang_exit_to_settings()` 中，**所有页面重建完成后**才调用（见 7.3）。

### 10.3 为什么这样安全？

```
时间线：
  t1: i18n_set_lang()      → 设标记，不广播
  t2: 用户看到"切换成功"
  t3: 用户右滑返回
  t4: 重建 settings/menu   → 旧屏幕已删除
  t5: 销毁功能页屏幕       → 所有非 main 屏幕已清理
  t6: lv_scr_load_anim(settings_screen)
  t7: i18n_flush_lang_changed()
       └─ homepage_lang_changed_cb()
            └─ 此时活动屏幕是 settings_screen（非 lang_screen）
            └─ lang_screen 已被销毁，不存在悬空引用
            └─ 主页 label 字体可安全替换
```

## 11. 开发过程中的问题与解决方案

### 11.1 Bug1：语言页右滑返回失败（未切换语言时）

**现象**：进入语言页不切换语言，右滑无法返回设置页。

**根因**：进入语言页时，`lv_scr_load_anim(lang_screen, ...)` 会使旧的 `settings_screen` 触发 `SCREEN_UNLOADED` 事件，异步调用 `settings_page_deinit()` 销毁 `settings_screen` 并置空。右滑返回时 `settings_screen == NULL`，导致无屏幕可切。

**修复**：在 `lang_exit_to_settings()` 的 else 分支（未变更语言）中检查并重建：
```c
else {
    if (settings_screen == NULL) {  // 被卸载回调销毁了
        settings_screen = lv_obj_create(NULL);
        create_settings_page(settings_screen);
    }
    lv_scr_load_anim(settings_screen, ...);
}
```

### 11.2 Bug2：AI页状态文字未翻译

**现象**：切换语言后，AI页的"正在监听..."、"AI回复中..."等仍显示中文。

**根因**：voice_assistant.c 中使用了硬编码字符串而非 `i18n_get()`。

**最终落地方案**：单点映射层——调用方仍传中文常量，函数内 strcmp 匹配后替换为 i18n 文案（完整设计见 13.3，调用方的中文常量**是有意的映射 key，不要"修复"它们**）。

### 11.3 Bug3：切换语言后渲染崩溃（PC=0x00000000）

**现象**：切换语言时设备死机，串口日志显示 `Instruction access violation (PC=0x00000000)`。

**根因**：同步广播导致 `lang_screen` 上的 label 引用已删除的 FreeType 字体。

**修复**：实现延迟广播机制（见第 10 章）。

### 11.4 Bug4：英文模式下中文显示方框

**现象**：英文模式下语言页的"简体中文"选项显示为方框。

**根因**：`i18n_get_cjk_font()` 在英文模式下返回 NULL，label fallback 到 montserrat 字体（不含中文）。

**修复**：`i18n_get_cjk_font()` 始终调用 `i18n_ensure_cjk_font()` 确保字体已加载（见 5.4）。

### 11.5 Bug5：相机页标题未翻译

**现象**：切语言后相机页标题不刷新，维持旧语言。

**根因**：`camera_page_deinit()` 删除了屏幕对象但无法置空全局 `camera_screen` 指针（定义在 lvgldemo.c）。下次进入时 `menu_enter_camera_page()` 检测到 `camera_screen != NULL`，复用旧屏幕，文字不刷新。

**修复**：在 `lang_exit_to_settings()` 中手动置空：
```c
camera_page_deinit();
camera_screen = NULL;  // 手动置空，强制下次重建
```

### 11.6 Bug6：异步重建导致崩溃

**现象**：尝试用 `lvgl_dispatch_async(lang_rebuild_async_cb, NULL)` 异步重建页面时崩溃。

**根因**：异步在 timer handler 中执行，此时 LVGL 状态可能不一致。

**修复**：改为同步重建（直接在 `lang_exit_to_settings()` 中执行）。

### 11.7 Bug7：英文模式时钟字号偏小

**现象**：英文模式下时钟和日期字体比中文模式小很多。

**根因**：最初英文模式回退到 `montserrat_24`（24px），而非加载 MiSans 字体。

**修复**：
1. `i18n_apply_font()` 无条件使用 MiSans 28px
2. 主页时钟英文字号从 80px 调整为 100px，日期从 39px 调整为 48px

### 11.8 Bug8：WiFi 页面语言适配回退

**现象**：WiFi 页面切换语言后文字不刷新，且扫描按钮文字切换时按钮缩小。

**根因**：页面文字多，且扫描按钮用 `LV_SIZE_CONTENT` 宽度随文字长度变化。

**决策**：WiFi 页面不适配多语言，还原为固定英文显示。

**修复**：
1. 移除 wifi_page.c 中所有 `i18n_get()` 调用，改为硬编码英文字符串
2. 移除 `i18n_apply_font` 调用，改用 `lv_font_montserrat_24`
3. 扫描按钮宽度从 `LV_SIZE_CONTENT` 改为固定 240px（防随文字缩放）
4. 清理 i18n.h/i18n.c 中的 `STR_WIFI_*` 枚举和字符串表条目

（任何语言下 WiFi 页显示英文**不是 bug**）

### 13.2 AI 语言联动机制（UI 语言 → AI 全链路跟随）

`i18n_set_lang()` 切换语言时同步执行 4 条联动：

```
i18n_set_lang(lang)
 ├─① 写 /emmc/lang_config（持久化）
 ├─② dashscope_asr_set_image_reply_lang(i18n_lang_to_ai_reply(lang))
 │      → 图文智录 response.create 携带 "Reply in japanese"
 ├─③ dashscope_tts_set_voice(i18n_lang_to_tts_voice(lang))
 │      → TTS 音色（每次合成新建连接，下次合成自动生效）
 └─④ voice_assistant_request_lang_refresh() → 置待刷新标志
        → 主循环消费标志 → session.update 重发 instructions（"Always reply in japanese"）
          → WS 在线立即生效；离线时重连 open 按当前语言构建 instructions 兜底
```

开机兜底：`i18n_init()` 执行时 ai_agent 进程尚未启动，TTS 音色在 ai_agent 启动后由 voice_channel.c 重读 `/emmc/lang_config` 二次应用。

云端能力核实结论（2026-10 查官方文档）：

| 云端环节 | 模型/音色 | 日语支持 |
|---|---|---|
| AI 对话（语音全双工） | qwen3.5-omni-flash-realtime + Tina | ✅ 60+ 语言音频输入 / 30+ 语言语音输出 |
| TTS 播报 | qwen3-tts-flash-realtime + Cherry | ✅ Cherry 原生支持日语 |
| 图文智录回复 | 同对话链路（response.create 级语言指定） | ✅ |
| 会议转录 ASR | paraformer-realtime-v2 | ✅ 8 语种自动检测 |
| 会议总结 LLM | qwen3.8-flash + 语言分支提示词 | ✅ 提示词三分支（zh/en/ja）；2026-10 由额度耗尽的 qwen3.5-flash 切换 |

### 13.3 状态文案单点映射层（voice_assistant_update_status）

11.2 Bug2 的最终落地方案：**函数内单点映射层**（voice_assistant.c）——调用方仍传中文常量，函数内 `strcmp` 匹配后替换为 `i18n_get(STR_xxx)`：

```c
if (strcmp(status, "正在监听...") == 0) status = i18n_get(STR_AI_LISTENING);
else if (strcmp(status, "AI回复中...") == 0) status = i18n_get(STR_AI_REPLYING);
/* ... 网络连接中/网络已断开/飞书对话/消息筛选/文档查询 同理 */
```

要点：
- 调用方（19 处）**有意保留中文常量**作为映射 key，不要"修复"它们
- 传已翻译文案时 strcmp 不匹配会原样透传（显示正确但绕过映射层）
- 新增状态文案标准动作：i18n.h 加枚举 → 各语言表加条目 → 映射层加一个分支

## 14. 德/法/俄探针接入与回落机制（2026-10 补充）

> 本章记录在 zh/en/ja 三语基础上接入德/法/俄的**探针版**实现。核心引入两项永久性架构改进：**未翻译条目回落英文**与**语言页滚动容器**，后续语种继续复用。

### 14.1 探针式接入策略

全量接入一个新语言需翻译约 100 条；若字体字形缺失，全量翻译将全部作废。因此两步走：

| 阶段 | 内容 | 字符串量 |
|---|---|---|
| **探针版（已实现）** | 每语言只翻译 11 条关键串：3 语言名 + 菜单 3 项 + 设置语言 + 确认 + 切换成功 + AI 监听 + 会议完成；未翻译条目自动回落英文 | 3 × 11 = 33 条 |
| **全量版（已完成，见 15.1）** | 补齐剩余约 90 条 + 日期格式 + 提示音 | 每语言 94 条 |

探针串本身就是字体测试用例：语言页 **Русский** 标签含西里尔字母、**Français** 含 ç、德语探针含 ä ö ü，烧录后语言页一眼完成字体判决。

### 14.2 回落机制：未翻译条目自动显示英文（架构变更）

原 `i18n_get()` 对未填表项返回 NULL（传入 `lv_label_set_text` 有崩溃风险），事实上强制每表填满。探针版改为 **NULL → 英文表回落**：

```c
const char *i18n_get(str_id_t id)
{
    if (id < 0 || id >= STR_COUNT) return "";
    const char *s = s_strings[g_current_lang][id];
    if (s == NULL) s = s_strings[LANG_EN][id];   /* 未翻译条目回落英文 */
    return s ? s : "";
}
```

`i18n_get_prompt()` 同样处理（未建行 → NULL → 英文 wav）。工程收益：新语言**只需建行不需要填满**，翻译可分批交付每批烧录验证；调用方从此**不可能拿到 NULL**。

### 15.2 主页日期适配（xiaoq_page.c 分支改造）

**问题**：原 `homepage_update_datetime()` 只有中/英两分支，de/fr/ru 落入中日共通 else 分支，日期显示中文格式。

**修复**：扩为三分支，德法俄共用一行——**直接读各自语言表的 `STR_HOME_DATE_FMT` 渲染**，参数序（日, 月）：

```c
if (cur_lang == LANG_EN) {
    snprintf(buf, sizeof(buf), "%s %d", i18n_en_months[time_info.tm_mon], time_info.tm_mday);
} else if (cur_lang == LANG_DE || cur_lang == LANG_FR || cur_lang == LANG_RU) {
    snprintf(buf, sizeof(buf), i18n_get(STR_HOME_DATE_FMT), time_info.tm_mday, time_info.tm_mon + 1);
} else {
    snprintf(buf, sizeof(buf), "%d月%d日", time_info.tm_mon + 1, time_info.tm_mday);
}
```

格式差异（德 21.10. / 法 21/10 / 俄 21.10）由语言表数据驱动，代码零分支膨胀；三条格式串均为纯 `%d` 占位，无注入风险。

### 15.3 提示音母语化落地

20 条新音频（日/德/法/俄 × 5 场景）经合成、转码、adb 部署后，`s_prompts` 完成落位：LANG_JA 行英文 wav → `*_ja.wav`；LANG_DE/FR/RU 行 NULL → 各自母语音。六语模式下唤醒/WiFi 事件/静默超时全部播放母语音。完整合成部署流程见 **[语音提示音合成与部署全流程教程.md](语音提示音合成与部署全流程教程.md)**。

### 15.4 语言页标题与确认按钮同步刷新（lang_dialog.c）

**现象**：语言 A 切换到 B 后，提示"切换成功"已是 B 语言，但页面顶部标题"语言"仍是 A 语言，确认按钮同样未刷新。

**根因**：标题与按钮文字仅在页面创建时按当时语言设置，切换成功后无人刷新存量控件。

**修复**（4 处，原地刷新）：新增 `lang_confirm_lbl` 静态指针 → `lang_do_confirm()` 成功分支刷新标题与按钮文字为新语言 → `create_bottom_buttons()` 保存 label 指针 → `lang_page_deinit()` 销毁时置空防悬垂。

**设计依据**：复用主页原地刷新模式——只 `lv_label_set_text()` 不重建屏幕，零性能开销；字体无需重设（`i18n_apply_font` 统一用 s_cjk_font，MiSans 六语字形全覆盖且切语言不删字体）。刻意避开重建 lang_screen（历史上异步重建曾引发 LVGL 崩溃，见 Bug3/Bug6）。

### 15.5 语种边界终局结论

**判定公式：可行语种 = 会议 ASR 支持 ∩ UI 字体支持 的最大交集 = {zh, en, ja, de, fr, ru}**

| 候选语言 | UI 字体（MiSans-Normal.ttf） | 会议 ASR（paraformer-realtime-v2） | 结论 |
|---------|------|------|------|
| 韩语 | ❌ 缺谚文（真机实测字幕矩形乱码，需 MiSans Global 或 Noto Sans CJK KR） | ✅ 识别质量已验证 | **放弃**（决策：不切换字体） |
| 西班牙语/葡语/意语 | ✅ 拉丁+变音符（与已验证的德法同区块） | ❌ 不在八语种清单 | **放弃**（UI 能做但会议链路缺失，只做 UI 是半成品） |
| 粤语 | ✅ 汉字零风险 | ✅ 支持 | **搁置**（模型输出为粤文书面语，产品预期形态未定） |

依据存档：ASR 八语种 = zh/en/ja/yue/ko/de/fr/ru（[meeting_transcription_feature.md](meeting_transcription_feature.md) 16.1）；字体覆盖见 14.8。六语即当前能力对齐线上的最大集合——"能做的全做了，做不了的各有明确技术理由"，此结论构成完整的工程边界说明。

   ```c
       if (xxx_screen) { lv_obj_del(xxx_screen); xxx_screen = NULL; }  // 关键！
   }
   ```
