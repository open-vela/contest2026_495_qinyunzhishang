## 1. 功能概述

### 1.1 功能定义

本系统运行在 BES2800BP 芯片上的 NuttX RTOS 实时操作系统中，通过 LVGL 图形界面提供用户交互。系统集成了飞书（Feishu/Lark）开放平台 API，实现两大核心功能：

| 功能 | 说明 |
|------|------|
| **图片上传至飞书** | 用户点击"AI 分析"按钮后，系统将摄像头拍摄的图片通过 HTTPS 上传到飞书服务器，并发送到指定的飞书群聊或用户 |
| **文字转发上传至飞书** | AI 大模型分析图片后产生的文字回复，以及用户语音对话的转录文字，自动转发到飞书群聊或用户 |

### 1.2 应用场景

```
┌─────────────────────────────────────────────────────────────┐
│                     完整业务流程                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 用户点击"拍照" → SPI 接收 2N 开发板传来的图片            │
│                                                             │
│  2. 用户点击"AI 分析"按钮                                    │
│     ├─ 创建飞书上传线程                                      │
│     │   ├─ Step 1: 获取目标 ID（open_id 或 chat_id）        │
│     │   ├─ Step 2: 上传图片到飞书 → 获得 image_key          │
│     │   └─ Step 3: 发送图片消息到指定群聊/用户               │
│     │                                                       │
│     └─ 创建 AI 分析线程                                      │
│         └─ 图片发送到大模型 → 获取分析结果                   │
│                                                             │
│  3. AI 回复文字自动转发到飞书（最多 3 轮）                   │
│     ├─ 图片分析结果                                          │
│     ├─ 用户语音对话 1 的回复                                 │
│     └─ 用户语音对话 2 的回复                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 预期目标

- **实时性**：图片上传在 3~5 秒内完成（取决于网络状况）
- **可靠性**：TLS 加密传输，保证数据安全
- **用户体验**：上传过程不阻塞 UI 界面（后台线程执行）
- **自动转发**：AI 回复自动转发，无需用户手动操作

## 3. 飞书 API 基础

### 3.1 API 认证机制详解

飞书 API 使用 **tenant_access_token**（应用访问令牌）进行认证：

```
┌──────────────┐                        ┌──────────────┐
│   AP 侧      │                        │  飞书服务器   │
│              │                        │              │
│  1. POST     │───HTTPS──────────────►│              │
│  /auth/v3/   │   {                    │  验证        │
│  tenant_     │    app_id,             │  app_id +    │
│  access_     │    app_secret          │  app_secret  │
│  token/      │  }                     │              │
│  internal    │                        │              │
│              │◄──HTTPS──────────────│              │
│  2. 接收     │   {                    │  生成        │
│  token       │    tenant_access_token,│  token       │
│              │    expire              │  (有效期2h)  │
│              │   }                    │              │
│              │                        │              │
│  3. 后续 API │───HTTPS──────────────►│              │
│  调用携带    │   Authorization:       │  验证 token  │
│  Bearer      │   Bearer <token>       │              │
│  token       │                        │              │
└──────────────┘                        └──────────────┘
```

**关键点**：
- token 有效期 2 小时（7200 秒）
- 系统提前 5 分钟（300 秒）刷新，避免过期
- token 存储在全局变量 `s_access_token` 中
- 使用 `s_token_lock` 互斥锁保护 token 读写

### 3.2 Access Token 获取流程

**API 接口**：`POST /open-apis/auth/v3/tenant_access_token/internal`

**请求体**：
```json
{
    "app_id": "cli_a1b2c3d4e5f6g7h8",
    "app_secret": "aB3cD4eF5gH6iJ7kL8mN9oP0qR1sT2uV3"
}
```

**响应体**：
```json
{
    "code": 0,
    "msg": "ok",
    "tenant_access_token": "t-xxxxx...",
    "expire": 7200
}
```

**实现代码**（[feishu_http.c](file:///home/lzw/code/si8658ca/openvela_005_0701/openvela_si8658ca/rtos/packages/ai_agent/src/channels/feishu_http.c)）：

```c
int feishu_get_app_token(void)
{
    char body[256];
    snprintf(body, sizeof(body), 
        "{\"app_id\":\"%s\",\"app_secret\":\"%s\"}",
        s_app_id, s_app_secret);

    char *resp = malloc(4096);
    // 发送 POST 请求（不需要 Authorization 头，因为这是获取 token 的请求）
    int status = feishu_https_post(
        "/open-apis/auth/v3/tenant_access_token/internal",
        NULL, body, resp, 4096);

    if (status != 200) { /* 错误处理 */ }

    cJSON *root = cJSON_Parse(resp);
    cJSON *tok = cJSON_GetObjectItem(root, "tenant_access_token");
    cJSON *expire = cJSON_GetObjectItem(root, "expire");

    // 加锁保护 token 写入
    pthread_mutex_lock(&s_token_lock);
    strncpy(s_access_token, tok->valuestring, sizeof(s_access_token) - 1);
    
    // 计算过期时间（当前时间 + expire - 300秒提前量）
    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);
    s_token_expire_ts = ts.tv_sec + (int64_t)expire->valuedouble - 300;
    pthread_mutex_unlock(&s_token_lock);

    return OK;
}
```

### 3.3 Token 过期检查机制

```c
bool feishu_token_expired(void)
{
    pthread_mutex_lock(&s_token_lock);
    bool empty = (s_access_token[0] == '\0');
    int64_t expire_ts = s_token_expire_ts;
    pthread_mutex_unlock(&s_token_lock);
    
    if (empty) return true;  // token 为空，需要获取
    
    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);
    return ts.tv_sec >= expire_ts;  // 当前时间 >= 过期时间
}
```

所有飞书 API 调用遵循统一格式：


## 4. 网络通信基础

### 4.1 飞书 TLS 握手完整流程详解

飞书 API 通过 HTTPS（HTTP over TLS）通信。TLS 握手是建立加密连接的关键步骤。

#### 4.1.1 TCP 三次握手（TLS 之前）

```
AP 侧                                      open.feishu.cn (443)
   │                                              │
   │  1. SYN (seq=x)                              │
   │─────────────────────────────────────────────►│
   │  2. SYN-ACK (seq=y, ack=x+1)                 │
   │◄─────────────────────────────────────────────│
   │  3. ACK (ack=y+1)                            │
   │─────────────────────────────────────────────►│
   │                                              │
   │  TCP 连接建立完成，可以开始 TLS 握手           │
```

**实现**（[vela_tls.c](file:///home/lzw/code/si8658ca/openvela_005_0701/openvela_si8658ca/rtos/packages/ai_agent/src/infra/vela_tls.c) 中 `mbedtls_net_connect`）：
```c
// mbedtls_net_connect 内部：

ret = mbedtls_net_connect(&ctx->net, host, port, MBEDTLS_NET_PROTO_TCP);

```

```
   │                                              │
   │  ┌─────────────────────────────────────┐    │

   │  │ - SNI: open.feishu.cn               │    │
   │  └─────────────────────────────────────┘    │
   │─────────────────────────────────────────────►│
   │                                              │
   │  ┌─────────────────────────────────────┐    │
   │  │ 阶段 2: ServerHello + Certificate    │    │
   │  │ - 选定的 TLS 版本和加密套件          │    │
   │  │ - server_random (32字节)            │    │
   │  │ - 服务器证书链 (X.509)              │    │
   │  │ - ServerKeyExchange (DH/ECDH 参数)  │    │
   │  │ - ServerHelloDone                   │    │
   │  └─────────────────────────────────────┘    │
   │◄─────────────────────────────────────────────│
   │                                              │
   │  ┌─────────────────────────────────────┐    │
   │  │ 阶段 3: 证书验证 + 密钥交换          │    │
   │  │ - 验证证书签名链 (VERIFY_OPTIONAL)  │    │

   │  └─────────────────────────────────────┘    │
   │─────────────────────────────────────────────►│

   │  ┌─────────────────────────────────────┐    │
   │  │ 阶段 4: 服务器确认                   │    │
   │  │ - ChangeCipherSpec                  │    │
   │  │ - Finished (加密)                   │    │
   │  └─────────────────────────────────────┘    │
   │◄─────────────────────────────────────────────│
   │                                              │
```

**实现代码**（[vela_tls.c](file:///home/lzw/code/si8658ca/openvela_005_0701/openvela_si8658ca/rtos/packages/ai_agent/src/infra/vela_tls.c) 中 `tls_ctx_connect`）：

```c
static int tls_ctx_connect(tls_ctx_t* ctx, const char* host, const char* port)
{
    // 1. 初始化 mbedTLS 各组件
    mbedtls_ssl_init(&ctx->ssl);
    mbedtls_ssl_config_init(&ctx->cfg);
    mbedtls_net_init(&ctx->net);
    mbedtls_ctr_drbg_init(&ctx->ctr_drbg);

    // 2. 初始化随机数生成器（TLS 握手需要随机数）
    mbedtls_ctr_drbg_seed(&ctx->ctr_drbg, simple_entropy_func, NULL, ...);

    // 3. 检查系统时间（TLS 证书验证需要正确时间）
    time_t now = time(NULL);
    if (now < 1704067200) {  // 2024年1月1日之前
        // 时间太旧，强制设置为 2026 年
        clock_settime(CLOCK_REALTIME, &ts);
    }

    // 4. TCP 连接（三次握手）
    mbedtls_net_connect(&ctx->net, host, port, MBEDTLS_NET_PROTO_TCP);

    // 5. 设置阻塞模式 + 读取超时
    mbedtls_net_set_block(&ctx->net);
    setsockopt(ctx->net.fd, SOL_SOCKET, SO_RCVTIMEO, &tv, sizeof(tv));

    // 6. 配置 SSL 参数
    mbedtls_ssl_config_defaults(&ctx->cfg, 
        MBEDTLS_SSL_IS_CLIENT,           // 客户端模式
        MBEDTLS_SSL_TRANSPORT_STREAM,    // TLS 流式传输
        MBEDTLS_SSL_PRESET_DEFAULT);     // 默认安全级别

    // 7. 设置 TLS 版本范围（1.2 ~ 1.3）
    mbedtls_ssl_conf_min_tls_version(&ctx->cfg, MBEDTLS_SSL_VERSION_TLS1_2);
    #if defined(MBEDTLS_SSL_PROTO_TLS1_3)
    mbedtls_ssl_conf_max_tls_version(&ctx->cfg, MBEDTLS_SSL_VERSION_TLS1_3);
    #else
    mbedtls_ssl_conf_max_tls_version(&ctx->cfg, MBEDTLS_SSL_VERSION_TLS1_2);
    #endif

    // 8. 设置 ALPN（告诉服务器我们用 http/1.1）
    static const char* alpn_protos[] = { "http/1.1", NULL };
    mbedtls_ssl_conf_alpn_protocols(&ctx->cfg, alpn_protos);

    // 9. 证书验证模式（OPTIONAL = 可选验证，无 CA 证书时不强制）
    mbedtls_ssl_conf_authmode(&ctx->cfg, MBEDTLS_SSL_VERIFY_OPTIONAL);

    // 10. 设置主机名（SNI，Server Name Indication）
    mbedtls_ssl_set_hostname(&ctx->ssl, host);

    // 11. 执行 TLS 握手（循环处理 WANT_READ/WANT_WRITE）
    while ((ret = mbedtls_ssl_handshake(&ctx->ssl)) != 0) {
        if (ret != MBEDTLS_ERR_SSL_WANT_READ && 
            ret != MBEDTLS_ERR_SSL_WANT_WRITE) {
            // 握手失败
            return VELA_TLS_ERR_HANDSHAKE;
        }
    }

    syslog(LOG_INFO, "Handshake OK: %s / %s\n", 
        mbedtls_ssl_get_version(&ctx->ssl),     // TLS 1.2 或 1.3
        mbedtls_ssl_get_ciphersuite(&ctx->ssl)); // 使用的加密套件

    return 0;
}
```

#### 4.1.3 证书验证过程

本系统使用 `MBEDTLS_SSL_VERIFY_OPTIONAL`（可选验证）模式：

| 模式 | 行为 | 本系统选择 |
|------|------|-----------|
| `MBEDTLS_SSL_VERIFY_REQUIRED` | 严格验证，证书无效则握手失败 | ❌（需要 CA 证书） |
| `MBEDTLS_SSL_VERIFY_OPTIONAL` | 验证但不禁用握手，错误仅记录日志 | ✅ |
| `MBEDTLS_SSL_VERIFY_NONE` | 不验证 | ❌（不安全） |

**为什么用 OPTIONAL**：NuttX 嵌入式系统没有内置 CA 证书库，加载完整 CA 链需要额外存储空间。OPTIONAL 模式保持兼容性同时记录验证结果。

### 4.2 HTTPS 通信原理

```
┌──────────┐                              ┌──────────┐
│  AP 侧   │                              │ 飞书服务器 │
│          │    TLS 加密通道               │          │
│  HTTP    │  ┌──────────────────────┐   │  HTTP    │
│  请求 ───┼─►│ 加密: 明文 → 密文     │──►│  请求    │
│          │  │                      │   │          │
│  HTTP    │  │◄─── 密文 → 明文 ─────│   │  HTTP    │

│          │  └──────────────────────┘   │          │
└──────────┘                              └──────────┘

应用层: HTTP/1.1 (POST /open-apis/...)

网络层: IP (路由)
```

### 4.3 TLS 连接池机制

为避免每次 API 调用都重新握手（耗时 1~2 秒），系统实现了 TLS 连接池：

```c
// vela_tls.c
#define CONN_POOL_SIZE 2  // 连接池大小
static conn_slot_t s_pool[CONN_POOL_SIZE];  // 连接池数组

typedef struct {
    tls_ctx_t ctx;        // TLS 上下文
    char host[128];       // 目标主机
    char port[8];         // 端口
    bool valid;           // 连接是否有效
    bool in_use;          // 是否正在使用
} conn_slot_t;
```

**连接池工作流程**：

```
1. 首次请求 open.feishu.cn:
   pool_acquire() → 找空 slot → tls_ctx_connect() → TLS 握手
   → 发送 HTTP 请求 → 接收响应
   → pool_release(keep=true) → 保留连接

2. 第二次请求 open.feishu.cn:
   pool_acquire() → 找到已存在的连接 → 复用！
   → 直接发送 HTTP 请求（跳过 TLS 握手）
   → 接收响应
   → pool_release(keep=true)

3. 连接断开时:
   pool_release(keep=false) → tls_ctx_free() → 关闭 socket
```

### 5.2 线程创建与参数传递

```c
// camera_page.c

// 线程参数结构体
typedef struct {
    char image_path[64];    // 图片文件路径
    bool start_ai_after;    // 飞书完成后是否启动 AI 分析
} cam_feishu_arg_t;

// 启动飞书上传线程
static void cam_send_to_feishu_async(const char *image_path, bool start_ai_after)
{
    // 1. 堆分配参数（线程结束后由线程自己 free）
    cam_feishu_arg_t *fa = malloc(sizeof(cam_feishu_arg_t));
    if (!fa) {
        syslog(LOG_ERR, "[FEISHU] OOM for thread arg\n");
        return;
    }
    strncpy(fa->image_path, image_path, sizeof(fa->image_path) - 1);
    fa->image_path[sizeof(fa->image_path) - 1] = '\0';
    fa->start_ai_after = start_ai_after;

    // 2. 创建线程
    pthread_t tid;
    pthread_attr_t attr;
    pthread_attr_init(&attr);
    pthread_attr_setstacksize(&attr, 128 * 1024);  // 128KB 栈
    // TLS 握手 + multipart 构造 + cJSON + fread 需要较大栈
    pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
    // 分离状态：线程结束自动回收资源，不需要 join
    int ret = pthread_create(&tid, &attr, cam_feishu_thread, fa);
    pthread_attr_destroy(&attr);

    if (ret != 0) {
        syslog(LOG_ERR, "[FEISHU] pthread_create failed: %d\n", ret);
        free(fa);  // 创建失败需要手动释放
    }
}
```

#### 5.4.2 multipart/form-data 格式构造

飞书图片上传 API 要求使用 `multipart/form-data` 格式（不是 JSON）：

```
------VelAFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="image"; filename="photo_001.jpg"

------VelAFormBoundary7MA4YWxkTrZu0gW--
```

**构造代码**（[feishu_send.c](file:///home/lzw/code/si8658ca/openvela_005_0701/openvela_si8658ca/rtos/packages/ai_agent/src/channels/feishu_send.c)）：

```c
static char *build_multipart_body(const char *filename,
                                   const uint8_t *file_data, size_t file_size,
                                   const char *boundary, size_t *out_len)
{
    // 分隔符格式：--boundary\r\n
    // 字段1: image_type = "message"（表示用于消息发送）
    const char *fmt1 =
        "--%s\r\n"
        "Content-Disposition: form-data; name=\"image_type\"\r\n"
        "\r\n";
    const char *val1 = "message";
    
    // 字段2: image = <文件数据>
    const char *fmt2 =
        "--%s\r\n"
        "Content-Disposition: form-data; name=\"image\"; filename=\"%s\"\r\n"
        "Content-Type: image/jpeg\r\n"
        "\r\n";
    
    // 结束标记
    const char *fmt3 = "--%s--\r\n";

    // 计算总长度并分配内存
    *out_len = h1 + v1 + 2 + h2 + file_size + 2 + h3;
    char *body = malloc(*out_len + 1);

    // 逐段拼接
    char *p = body;
    p += sprintf(p, fmt1, boundary);          // 字段1头部
    memcpy(p, val1, v1); p += v1;             // 字段1值
    memcpy(p, "\r\n", 2); p += 2;             // 分隔
    p += sprintf(p, fmt2, boundary, filename); // 字段2头部
    memcpy(p, file_data, file_size); p += file_size;  // 图片二进制数据
    memcpy(p, "\r\n", 2); p += 2;             // 分隔
    p += sprintf(p, fmt3, boundary);          // 结束标记

    return body;
}
```

### 6.4 分块发送机制

飞书单条消息有长度限制（约 30KB），超长文字需要分块发送：

```c
static int send_message_chunks_ex(const char* receive_id, const char* text,
                                    size_t text_len, const char* id_type)
{
    char api_path[256];
    snprintf(api_path, sizeof(api_path),
        "/open-apis/im/v1/messages?receive_id_type=%s", id_type);

    size_t offset = 0;
    while (offset < text_len) {
        size_t chunk = text_len - offset;

        // 超过最大长度时分块
        if (chunk > AGENT_FEISHU_MAX_MSG_LEN) {
            chunk = AGENT_FEISHU_MAX_MSG_LEN;
            // 避免在 UTF-8 字符中间截断
            // UTF-8 后续字节以 10xxxxxx (0x80~0xBF) 开头
            while (chunk > 0 &&
                   ((unsigned char)text[offset + chunk] & 0xC0) == 0x80) {
                chunk--;
            }
        }

        // 提取分块文本
        char* seg = malloc(chunk + 1);
        memcpy(seg, text + offset, chunk);
        seg[chunk] = '\0';

        // 构造 content JSON
        cJSON* content_obj = cJSON_CreateObject();
        cJSON_AddStringToObject(content_obj, "text", seg);
        char* content_str = cJSON_PrintUnformatted(content_obj);
        cJSON_Delete(content_obj);
        free(seg);

        // 构造完整请求体
        cJSON* body_obj = cJSON_CreateObject();
        cJSON_AddStringToObject(body_obj, "receive_id", receive_id);
        cJSON_AddStringToObject(body_obj, "msg_type", "text");
        cJSON_AddStringToObject(body_obj, "content", content_str);
        char* body_str = cJSON_PrintUnformatted(body_obj);
        cJSON_Delete(body_obj);
        free(content_str);

        // 发送请求
        int status = feishu_https_post(api_path, hdrs, body_str, resp, 4096);

        // token 过期自动刷新重试
        if (status == 400 && strstr(resp, "access token")) {
            feishu_get_app_token();  // 刷新 token
            status = feishu_https_post(api_path, retry_hdrs, body_str, resp, 4096);
        }

        offset += chunk;  // 移动到下一块
    }
    return OK;
}
```

## 8. 常见问题及解决方案详细记录

### 8.1 问题一：飞书线程导致 LVGL 界面卡死

**这是本项目中遇到的最严重问题，有专门文档记录。**

#### 8.1.1 问题现象

点击"AI 分析"按钮后，界面永久卡死（无法滑动/点击），但飞书上传和 AI 分析功能正常运行。

#### 8.1.2 排查过程

1. **优先级排查**：降低飞书线程优先级 → 无效
2. **分步屏蔽**：屏蔽图片上传仍卡死 → 问题在 TLS 本身
3. **INDEV 诊断**：`fcntl(F_GETFD)` 发现触摸 fd=4 的 CLOEXEC 标志变化
4. **fstat 终极诊断**：`chr: 1→0, sock: 0→1` 确认 fd=4 从触摸设备变成 socket

#### 8.1.3 根因

飞书 TLS 的 `socket()` 系统调用复用了被释放的 fd=4（触摸设备），导致 LVGL 的 `uv_poll` 监听到错误的 fd。

#### 8.1.4 解决方案

在 `lvgldemo.c` 的 `lv_nuttx_init` 后添加 fd 重定位：

```c
if (result.indev) {
    void *drv_data = lv_indev_get_driver_data(result.indev);
    if (drv_data) {
        int touch_fd = *(int *)drv_data;
        if (touch_fd >= 0 && touch_fd < 20) {
            int new_fd = fcntl(touch_fd, F_DUPFD, 20);  // 复制到 fd≥20
            if (new_fd >= 0) {
                *(int *)drv_data = new_fd;  // 更新 driver_data
                // 不关闭 fd=4，保留作为占位符
            }
        }
    }
}
```

详见 [飞书TLS导致界面卡死问题定位总结.md](file:///home/lzw/code/si8658ca/openvela_005_0701/openvela_si8658ca/doc/飞书TLS导致界面卡死问题定位总结.md)。

### 8.2 问题二：TLS 连接池误关闭 fd=0

#### 8.2.1 问题现象

系统启动后第一次飞书 API 调用偶发失败，日志显示 `close(0)` 异常。

#### 8.2.2 根因

`s_pool` 是 BSS 静态数组，`ctx.net.fd` 默认值为 0（不是 -1）。`tls_ctx_free` 调用 `mbedtls_net_free` 时，`fd=0` 不等于 `-1`，导致 `close(0)` 误关闭标准输入。

#### 8.2.3 解决方案

```c
// pool_acquire 分配空 slot 时显式设置 fd=-1
s_pool[i].in_use = true;
s_pool[i].ctx.net.fd = -1;  // 防止误关闭 fd=0
```

### 8.3 问题三：TLS 握手失败 "Clock too old"

#### 8.3.1 问题现象

TLS 握手失败，日志显示证书验证错误。

#### 8.3.2 根因

NuttX 系统时间不正确（停留在 1970 年），导致 TLS 证书有效期验证失败。

#### 8.3.3 解决方案

```c
time_t now = time(NULL);
if (now < 1704067200) {  // 2024年1月1日之前
    syslog(LOG_WARNING, "Clock too old, forcing to 2026\n");
    struct timespec ts = { .tv_sec = 1772275200, .tv_nsec = 0 };
    clock_settime(CLOCK_REALTIME, &ts);
}
```

### 8.4 问题四：ALPN 未设置导致服务器拒绝连接

#### 8.4.1 问题现象

部分 HTTPS 服务器（如 Cloudflare）在 TLS 握手阶段直接关闭连接。

#### 8.4.2 根因

现代 HTTPS 服务器要求 ClientHello 包含 ALPN（Application-Layer Protocol Negotiation）扩展，否则可能拒绝连接。

#### 8.4.3 解决方案

```c
static const char* alpn_protos[] = { "http/1.1", NULL };
mbedtls_ssl_conf_alpn_protocols(&ctx->cfg, alpn_protos);
```

### 8.5 问题五：长消息发送失败

#### 8.5.1 问题现象

AI 回复文字较长时（超过 30KB），飞书 API 返回错误。

#### 8.5.2 解决方案

实现分块发送机制，避免在 UTF-8 字符中间截断（见 §6.4）。

### 8.6 预防措施建议

| 措施 | 说明 |
|------|------|
| fd 重定位 | 所有关键 fd（触摸、显示）移到高 fd 区间（≥20）|
| 连接池初始化 | BSS 数组的 fd 字段显式设为 -1 |
| 系统时间检查 | TLS 握手前检查时间是否合理 |
| ALPN 设置 | 始终设置 ALPN 为 http/1.1 |
| 分块发送 | 长消息自动分块，避免 UTF-8 截断 |
| Token 自动刷新 | 过期前 5 分钟自动刷新 |
| 线程安全 | token 读写用互斥锁保护 |

```c
// camera_page.c

static void *cam_feishu_thread(void *arg)
{
    cam_feishu_arg_t *fa = (cam_feishu_arg_t *)arg;
    char receive_id[64] = {0};
    const char *id_type = "chat_id";

    // Step 0: 检查飞书是否已配置
    const char *app_id = feishu_get_app_id();
    if (!app_id || app_id[0] == '\0') {
        syslog(LOG_ERR, "[FEISHU] App not configured, skip\n");
        if (fa->start_ai_after)
            lvgl_dispatch_async(cam_feishu_done_cb, (void *)(intptr_t)0);
        free(fa);
        return NULL;
    }

    // Step 1: 根据配置搜索目标
#if AGENT_SECRET_FEISHU_TARGET_TYPE == 1
    // 模式1：通过手机号获取用户 open_id
    if (feishu_get_user_open_id(AGENT_SECRET_FEISHU_TARGET_MOBILE,
                                 receive_id, sizeof(receive_id)) != 0) {
        if (fa->start_ai_after)
            lvgl_dispatch_async(cam_feishu_done_cb, (void *)(intptr_t)0);
        free(fa);
        return NULL;
    }
    id_type = "open_id";
#else
    // 模式0：通过群名搜索 chat_id
    if (feishu_search_chats(AGENT_SECRET_FEISHU_TARGET_CHAT,
                             receive_id, sizeof(receive_id)) != 0) {
        if (fa->start_ai_after)
            lvgl_dispatch_async(cam_feishu_done_cb, (void *)(intptr_t)0);
        free(fa);
        return NULL;
    }
#endif

    // Step 2: 上传图片到飞书
    char image_key[128] = {0};
    if (feishu_upload_image(fa->image_path, image_key,
                             sizeof(image_key)) != 0) {
        if (fa->start_ai_after)
            lvgl_dispatch_async(cam_feishu_done_cb, (void *)(intptr_t)0);
        free(fa);
        return NULL;
    }

    // Step 3: 发送图片消息
    if (feishu_send_image_message_ex(receive_id, image_key,
                                      id_type) != 0) {
        if (fa->start_ai_after)
            lvgl_dispatch_async(cam_feishu_done_cb, (void *)(intptr_t)0);
        free(fa);
        return NULL;
    }

    // 保存 receive_id 和 id_type 供文字转发使用
    strncpy(s_feishu_receive_id, receive_id, sizeof(s_feishu_receive_id) - 1);
    s_feishu_id_type = (strcmp(id_type, "open_id") == 0) ? "open_id" : "chat_id";

    // 成功完成，通知 UI
    if (fa->start_ai_after)
        lvgl_dispatch_async(cam_feishu_done_cb, (void *)(intptr_t)1);

    free(fa);
    return NULL;
}
```

### 10.5 完整的文字转发线程代码

```c
// voice_assistant.c

// 转发线程：阻塞式发送飞书文本，避免拖慢 WS 接收线程
static void *feishu_fwd_thread(void *arg)
{
    fwd_arg_t *fa = (fwd_arg_t *)arg;
    int ret = feishu_send_text_message_ex(fa->receive_id,
                                           fa->text, fa->id_type);
    if (ret != 0) {
        syslog(LOG_WARNING, "feishu fwd FAILED: %d\n", ret);
    } else {
        syslog(LOG_INFO, "feishu fwd OK: %.80s\n", fa->text);
    }
    free(fa);
    return NULL;
}

// 在 WS 接收线程调用，必须非阻塞：拷贝文本并 spawn detached 线程
static void feishu_fwd_dispatch(const char *prefix, const char *content)
{
    if (!s_fwd_enabled || !content || content[0] == '\0') return;
    if (s_fwd_receive_id[0] == '\0') return;
    if (s_fwd_ai_count >= FEISHU_FWD_MAX_AI_REPLIES) {
        s_fwd_enabled = false;
        return;
    }
    s_fwd_ai_count++;

    fwd_arg_t *fa = malloc(sizeof(fwd_arg_t));
    if (!fa) return;
    snprintf(fa->text, sizeof(fa->text), "%s%s", prefix, content);
    strncpy(fa->receive_id, s_fwd_receive_id, sizeof(fa->receive_id) - 1);
    strncpy(fa->id_type, s_fwd_id_type, sizeof(fa->id_type) - 1);

    pthread_t tid;
    pthread_attr_t attr;
    pthread_attr_init(&attr);
    pthread_attr_setstacksize(&attr, 64 * 1024);
    pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
    if (pthread_create(&tid, &attr, feishu_fwd_thread, fa) != 0) {
        free(fa);
    }
    pthread_attr_destroy(&attr);
}
```

### 10.7 关键设计原则

1. **线程隔离**：所有网络阻塞操作在独立线程执行，不阻塞 UI 主线程
2. **分离线程**：使用 `PTHREAD_CREATE_DETACHED`，线程结束自动回收
3. **堆分配参数**：线程参数通过 `malloc` 分配，线程内 `free`
4. **回调通知 UI**：通过 `lvgl_dispatch_async` 在主线程执行 UI 更新
5. **Token 自动管理**：API 调用前检查过期，失败时自动刷新重试
6. **连接池复用**：TLS 连接保持 keep-alive，减少握手开销
7. **分块发送**：长消息自动分块，避免 UTF-8 字符截断
8. **错误隔离**：飞书失败不影响本地 AI 分析和语音播放
