# 全录智伴 —— 端云协同 AI 智能产品，赋能办公自动化

基于 OpenVela OS（NuttX RTOS）与 BES2800 BP 芯片打造的端云协同轻量化 AI 办公终端：以 AI 语音对话为核心交互，深度集成飞书生态，覆盖办公信息从采集、处理到归档的全流程自动化。本作品由华勤技术软件中心三部自主立项开发，作为 2026 首届 OpenVela AI 硬件开发者大赛参赛作品（队伍「勤云之上」，编号 495）。

## 一、作品简介

传统办公中，会议记录依赖人工速记易遗漏，拍照分析需掏出手机操作繁琐，飞书文档、群聊消息、会议记录分散各处缺乏统一入口。本作品在 BES2800 BP 嵌入式平台上构建了可独立运行的轻量化 AI 办公终端——无需掏出手机，开口即能对话、入会即出纪要、拍照即得解析、一句话即获群聊要闻，让 AI 办公能力真正随身携带、随叫随到。

### 核心功能

#### 1. AI 语音对话 —— 即说即应的随身智能助手

- **全双工流式交互**：说话、停止、应答一气呵成，对话响应延迟 ≤2s，交流体验接近自然对话
- **三合一模型架构**：Qwen-Omni-Realtime 通过**单条 WebSocket** 同时完成语音识别、大模型对话、语音合成，避免三次独立调用的累积延迟
- **常连接设计**：空闲期保持 WebSocket 预连接不断开，配合硬件 VAD 持续检测，无需等待唤醒后的连接建立
- **流式播报**：TTS 按标点分段合成、边合成边播报，长回复不卡顿
- **智能省电调度**：对话前提前关闭 WiFi 省电模式消除下行音频抖动，结束后延迟恢复，兼顾流畅与功耗

#### 2. 飞书生态深度集成 —— 办公信息的统一智能入口

- **飞书文档语音播报**：说一句“念一下某某文档”，设备经 OAuth2 拉取文档全文，LLM 提炼要点后 TTS 播报——会议开始前一分钟，用它快速了解文档背景
- **今日消息归纳**：一句话获取指定群聊当日要闻，由 qwen3.8-flash 归纳成摘要播报——无需逐条刷群，重要信息不遗漏
- **飞书群聊机器人**：设备以长连接接入群聊，同事在群里发消息，AI 自动理解并回复——人不在工位，群聊不缺席
- **意图快速路由**：本地关键词匹配命中（文档名、群聊名、“今日消息”等）直接走飞书 API 快速路径，不经过大模型，响应更快、token 更省
- **全功能闭环**：会议纪要（功能 3）与拍照解析结果（功能 4）均自动归档至飞书，信息采集到沉淀一条链路打通

#### 3. 会议实时转录 —— 会开完，纪要已成

- **多语言流式识别**：基于 Paraformer-realtime-v2，识别准确率 ≥98%，转写文本实时上屏，说话即见
- **多语言原生支持**：向设备 `/emmc/asr_lang_hints` 写入语言代码（如 `ja`）即可切换识别语种，**无需重新编译或烧录**，零代码适配不同语种会议
- **纪要自动生成**：会议结束自动调用 qwen3.8-flash 将全文转录归纳为结构化纪要，经飞书 API 写入文档——散会即归档，会后零整理
- **弱网鲁棒**：弱网时动态调整发送缓冲容忍延迟；断网时纯本地 WAV 录音，网络恢复后自动重连并支持补传转录，内容不丢失

#### 4. 图文智录 —— 拍照 5 秒得结构化信息

- **双板协同采集**：主控下发拍照指令，Lubancat 2N（RK3568）驱动摄像头采集，经 SPI 24MHz 高速通道回传——BES 平台无摄像头能力瓶颈，RK3568 无 UI/通信能力短板，各展所长
- **分级传输**：缩略图秒级预览确认构图，原图按需获取，节省带宽与时间
- **云端多模态分析**：拍照后 ≤5s 输出关键信息（Qwen-Omni-Realtime 图像理解）——白板要点、名片信息、纸质文档，拍一下即刻结构化
- **多轮细节追问**：对同一张照片可持续追问细节（“第三点展开讲讲”），而非一次性问答
- **一键归档飞书**：解析结果直接写入飞书文档，纸质资料数字化即拍即存

#### 5. 蓝牙通话提醒 —— 不错过重要来电

- **标准 HFP 免提协议**：来电显示、接听、拒答、挂断全流程支持
- **线程安全设计**：蓝牙协议栈回调与 LVGL UI 经原子文件状态同步，规避跨线程操作 GUI 的竞态崩溃
- **完全本地运行**：不依赖网络，任何环境下可用

### 技术亮点

- **端云协同架构**：设备侧专注音频采集、UI 交互与数据传输，AI 重计算由云端承担——在嵌入式平台上实现接近自然对话的智能体验，同时保留断网降级能力
- **双板高速可靠传输**：UART（921600bps 控制平面）+ SPI（24MHz 数据平面）双通道，CRC16 校验 + 选择性重传 + 多级超时保护，实测缩略图 88KB 约 13s、原图 1MB 约 30s 稳定传输
- **飞书生态全链路闭环**：文档播报、消息归纳、群聊机器人、纪要归档、图文存档——飞书数据可在终端“读出来”，终端数据也能“存回去”
- **六语言全链路适配**：界面文字、日期格式与语音提示音覆盖中/英/日/德/法/俄，语言偏好设备端配置化，运行时生效

## 三、选题方向

**AI 硬件产品创新 — AI 办公助手**

选型理由：

1. **真实痛点驱动**：职场人士在移动场景下无法便捷获取 AI 办公能力——现有方案均依托手机或电脑大屏设备，尚未出现真正轻量化、可独立运行的办公终端
2. **硬件能力匹配**：BES2800 BP 集成 WiFi/BT 5.0 双模无线、PDM/I2S 双麦克风接口、硬件 VAD/KWS 唤醒引擎、OpenVela OS 官方适配完善——天然适合 AI 语音交互类应用
3. **端云协同最优解**：在有限算力下通过云端 AI 保障高质量智能体验（相比本地模型精度更高），同时保留断网降级能力（纯本地录音存储 + 网络恢复后补传）
4. **双板分工协作**：BES2800 BP 负责交互与通信（超低功耗、无线集成），RK3568 负责重计算（摄像头、图像处理），资源约束下的最优架构

## 四、系统架构与关键技术实现

本章从实现视角拆解端云协同、本地唤醒、会议转录、飞书集成四条核心链路，并归纳贯穿全模块的工程质量设计；所述设计与参数均对应仓库内源文件与技术文档，经真机验证。

### 4.1 端云协同：双模式语音引擎

```
【空闲模式】本地 VAD/KWS 常驻检测，云端连接仅 ping 保活，不上传音频
              │ 唤醒词「小Q小Q」命中
              ▼
【对话模式】停本地 VAD → 开云端麦克风 ──16kHz 音频流──► 云端 Qwen-Omni-Realtime
                                                    （单 WebSocket 同时完成识别+对话+合成）
```

- **系统状态机**：`IDLE → NETWORKING → ONLINE_WAKEUP → AI_RESPONSE` 四态显式管理网络/唤醒/对话全生命周期（`lvgldemo.c`）
- **空闲模式**：WebSocket 常连接仅 ping 保活、**不上传麦克风音频**，本地 VAD 持续检测——待机零云端算力、零流量消耗
- **对话模式**：唤醒后严格执行麦克风独占切换（`wakeup_detector_stop()` → 开录音器），16kHz/16bit 单声道音频流式上传
- **会话三态复用**：同一 WebSocket 承载对话/静音保活/图像分析——拍照解析时禁用本地 VAD、注入静音 PCM 维持会话心跳、图片帧注入后 `response.create` 触发推理，解析毕恢复 VAD（`voice_assistant.c`）
- **退出与韧性**：300s 无对话活动自动退出（用户语音事件、AI 音频增量、会话建立三处刷新计时）；服务端 300s 空闲断连（code=1007）由客户端自动重连；WiFi 断开由后台线程收尾并恢复本地 VAD 常驻检测

### 4.2 本地唤醒：TFLite Micro 两阶段流水线

唤醒检测完全在端侧运行，不依赖网络：

```
【音频预处理】16kHz 音频流 → 49×40 维声学特征（30ms 窗口 / 20ms 步进）
        │ 特征直接内存拷贝传递，无格式转换
        ▼
【语音分类】轻量卷积分类模型 → 三分类：静音 / 其他语音 / 唤醒词
```

**推理判决链**（`wakeup_detector.cpp`，模型仅约 15KB）：

| 环节   | 参数                | 设计意图             |
| ---- | ----------------- | ---------------- |
| 能量门控 | 短时能量低于 1200 时跳过推理 | 静音期零推理开销，功耗与性能兼得 |
| 唤醒阈值 | 唤醒词得分 ≥ 0.40      | 灵敏度与误唤醒率的平衡点     |
| 类别间隔 | 最高分−次高分 ≥ 0.10    | 滤除三类得分接近时的模糊判决   |
| 连续命中 | 1 帧（1 秒窗口、半秒步进）   | 半秒步进保证唤醒响应速度     |
| 唤醒冷却 | 3000ms            | 防止单次语音重复触发       |

**部署一致性自检**：两模型间特征直接拷贝传递，启动期自检预处理与分类环节的数值标度严格对齐（偏差小于 0.0001），从机制上确保模型更新后唤醒判定始终稳定。模型训练、压缩与部署的完整流程沉淀为 `skills/wakeup-detector/`。

**团队自建唤醒词语料库**：唤醒词识别的准确率高度依赖真实人声样本，我们组织同事录制了 2864 条「小Q小Q」唤醒词录音，远中近三档距离、安静/嘈吵双环境逐人录制，让模型学到的是真实使用场景中各具口音、音色与语速的“活”样本，而非干净实验室条件下的标准发音。同时自建三类互补负样本：Google 开源英文语音指令数据集的 34 类常用词（覆盖英文人声）、357 条中文近似词（如“小Q同学”），让模型学会“什么不是唤醒词”；配合背景噪声混合增强，嘈杂环境下依然可靠识别。原始录音经脚本自动清洗（去 pop 音、裁静音、统一时长）后方可入训，从源头保证数据质量。模型压缩至约 15KB 后识别准确率仍达 99.1%——在 15KB 体量内实现 99% 级准确率，是端侧资源约束下做唤醒词训练的上佳实践。

### 4.3 会议实时转录：双录音器与弱网韧性

会议场景要求“存档不丢”与“字幕实时”兼得，单一录音器无法同时满足 WAV 落盘与流式上传两种消费模式，故采用双录音器架构：

```
麦克风输入
  ├─► 录音器 1 ──► WAV 落盘（eMMC 存档，断网可用）
  └─► 录音器 2 ──► 云端流式识别 ──► 字幕实时上屏
```

- **时序设计**：进入会议页即预建传输层连接（TLS 握手与 WebSocket 升级提前完成），录音器就绪后先补发积压音频再切入实时流——消除“开口前三秒丢失”
- **字幕分行**：云端返回的句子序号增量驱动字幕换行，进度条忠实指示已转写时长
- **多语言零重编译**：识别语种由 `/emmc/asr_lang_hints` 文件内容决定（中/英/日/德/法/俄），运行时读取，切换语种无需改代码重新烧录
- **纪要归档**：会议结束自动将全文转录交由 qwen3.8-flash 归纳为结构化纪要，经飞书接口写入文档，散会即归档

**降级矩阵**（每一级都有可用产物，会议永不空手而归）：

| 网络状况   | 行为                    | 用户可见结果      |
| ------ | --------------------- | ----------- |
| 正常     | 双录音器并行，实时字幕 + WAV 存档  | 实时字幕、会后纪要   |
| 弱网     | 动态放宽发送缓冲容忍延迟，优先保证数据完整 | 字幕延迟增大，不丢内容 |
| 断网     | 仅本地 WAV 录音；网络恢复后自动重连  | 会后可补传转录     |
| 识别链路异常 | 降级为会后文件转录             | 纪要仍可生成      |

**稳定性设计**：转写链路为每个线程独立规划栈空间，网络读取与流解析均设多级超时保护，长时转写与多语言场景下运行稳定；工程细节见 `docs/meeting_transcription_feature.md`。

### 4.4 飞书快速路径：免大模型直达与回声抑制

飞书高频操作（建文档、查内容、搜关键词、听今日消息）若每次都绕大模型，响应慢且成本高。系统采用两层意图匹配架构：

```
语音识别文本
  ├─ 第一层（语音侧）：动作词+对象词命中（如“创建”+“飞书文档”）
  │    → 直接拦截，不走大模型，本地工具直达飞书接口
  └─ 未命中 → 正常进入大模型对话链路
```

- **响应提速**：快速路径不调用大模型，直接执行本地工具链路，响应延迟从秒级降至 2 秒内，同时节省 token 开销
- **凭证免授权**：飞书接入采用应用身份凭证，有效期 2 小时并提前 5 分钟自动续期，用户无需任何手动授权步骤
- **回声抑制**：播报期间自动暂停本机录音上传，待播报完成且回声消散（500ms）后恢复——避免设备自己播报的语音被云端误识别为用户提问，从机制上杜绝“自问自答”
- **长文本分段播报**：文档内容按标点智能切分、逐段合成播报，段间动态等待音频缓冲消化，最多可朗读约 2700 字的完整文档；朗读文本统一净化处理，过滤控制字符与无效符号，保证播报顺畅

### 4.5 工程质量：跨线程安全与资源纪律

嵌入式 GUI 与多线程音频/网络共存，工程质量设计贯穿全部模块：

- **跨线程 UI 安全**：LVGL 图形库非线程安全，所有非主线程的界面更新经统一派发队列投递，由主线程 5ms 周期消费——从架构上消除竞态崩溃
- **页面生命周期管理**：页面首次导航时才创建、离开即销毁，内存占用始终只有当前页面；页面卸载时重置输入设备引用，消除悬空指针
- **音频资源独占调度**：录音与播放共享同一音频管线，唤醒检测、语音对话、会议转录、本地播放器四类消费者严格按序切换，杜绝并发争用
- **条件编译适配**：WiFi、蓝牙、语音助手、唤醒检测、媒体框架均以独立编译开关裁剪，同一代码库适配不同硬件形态（含无屏版本，无屏时语音链路独立运行）
- **持久化设计**：WiFi 凭证、语言偏好、系统时间均落盘保存，重启后自动恢复，时间在无网环境下依然准确走时

## 六、运行方式

### 6.1 硬件环境

| 组件    | 型号/规格                     | 用途                             |
| ----- | ------------------------- | ------------------------------ |
| 主控开发板 | BES2800 BP（主频 320MHz）     | 运行 OpenVela OS + 主应用 + 蓝牙/WiFi |
| 辅助开发板 | Lubancat 2N（RK3568，Linux） | 图文智录场景：摄像头控制 + SPI 图像传输        |
| 显示屏   | 圆形 LCD（LVGL 驱动）           | 用户界面                           |
| 音频    | PDM/I2S 双麦克风 + 扬声器        | 语音采集与 TTS 播放                   |
| 存储    | eMMC                      | 固件、录音、壁纸、配置持久化                 |

### 6.2 编译说明

本作品以 OpenVela OS（NuttX RTOS）为系统底座，在集成 BES2800 平台支持包的内部工程环境中完成开发、编译与烧录，全部功能（含核心功能与飞书生态集成）均已在 BES2800 BP 真机上稳定运行。代码依赖 BES 平台特有组件：

1. **BES 板级支持包**：媒体服务框架（`media_recorder_open("Vad")`）、音频驱动接口（`af_stream` 系列）、硬件 VAD/KWS 引擎、蓝牙协议栈
2. **内部工程头文件路径**：lvgldemo 的 Makefile 使用 `$(APPDIR)/packages/ai_agent/include`，对应内部工程中 ai_agent 的原生位置

### 6.3 设备部署与运行

**前提条件**：已在内部工程环境完成编译并生成固件（`.bin`/`.elf`）

1. **烧录固件**至 BES2800 BP（使用 BES 平台烧录工具）

2. **推送壁纸资源**至设备 eMMC：
   
   ```bash
   adb push wallpapers/wallpaper.bin /emmc/wallpapers/
   adb push wallpapers/wallpaper2.bin /emmc/wallpapers/
   adb push wallpapers/wallpaper3.bin /emmc/wallpapers/
   adb push wallpapers/wallpaper4.bin /emmc/wallpapers/
   ```

3. **配置运行时参数**（通过设备 shell 或设置界面）：
   
   - API Key 等凭证经设备端配置存储（`claw_config`）加载，支持 `/emmc` 下密钥文件覆盖
   
   - `/emmc/asr_lang_hints`：语言偏好（文件不存在默认中英双语，写入 `ja` 切换日语等）
   
   - （可选）通过 `adb shell` 配置云端模型选择（各模型独立配置，避免冲突）：
     
     ```bash
     adb shell
     cd /emmc
     mkdir -p wifi && cd wifi
     echo "<DashScope API Key>" > agent_app_id
     echo "qwen3.5-omni-flash-realtime" > agent_asr_model
     echo "qwen3-tts-flash-realtime-2025-09-18" > agent_tts_model
     reboot
     ```
     
     > 模型名以阿里云百炼平台当前可用版本为准，上述为示例值。`agent_app_id` 文件内容即为 DashScope API Key。

4. **启动设备** → LVGL 界面自动加载 → 说“小Q小Q”唤醒 → 开始对话

### 6.4 密钥配置说明

云端模型服务（阿里云百炼）与飞书开放平台的接入凭证已按安全规范处理：仓库中 `app/ai_agent/include/agent_config.h` 的所有敏感默认值均为空字符串，设备运行时从配置存储读取真实凭证。

若需本地编译验证，可参考 `agent_config.h` 中 `AGENT_SECRET_*` 宏定义，在 `include/` 下创建 `agent_secrets.h` 填入自己的密钥（该文件已被 `.gitignore` 排除，不会进入版本控制）。

### 7.1 开发过程中的 AI 协作

### 7.2 开发沉淀：SKILL 与技术文档

**5 个自定义开发 Skill**（`app/lvgldemo/skills/`）：将团队在特定工程任务中反复验证的方法沉淀为结构化操作手册，AI 依此即可稳定复现专业级流程，同类项目可直接套用：

| Skill                     | 内容                                         |
| ------------------------- | ------------------------------------------ |
| `wakeup-detector`         | 唤醒词模型训练、量化部署与 5 轮迭代调优完整流程（含误唤醒问题排查）        |
| `build-log-analyzer`      | NuttX/OpenVela 构建日志分析方法论与代码定位流程            |
| `feishu-doc-voice-create` | 飞书文档语音创建与查询的快速路径（OAuth2 + LLM 总结 + TTS 播报） |
| `lvgldemo`                | 主应用架构总纲：状态机、页面导航、模块职责边界                    |
| `best1700-dmic`           | 数字麦克风通道配置、录音增益调优、双通道同时录制                   |

**11 份技术文档**（`app/lvgldemo/docs/`，开发过程记录与踩坑经验）：涵盖会议转录、双板通信、图文智录、飞书集成、i18n、提示音合成、UI 设计等，详见目录结构章节。

**37 个运行时 Agent 技能**（`app/ai_agent/agent_skills/`）：技能是设备端 AI Agent 的可插拔能力单元，每个技能是一个结构化 Markdown，声明**触发意图**（When to use）、**工具编排流程**（How to use）与**对话样例**（Example）。系统启动时 `skill_loader` 将技能摘要注入 LLM 系统提示；用户语音命中意图后，Agent 按技能既定流程串接飞书 API、文件读写、网络搜索等已注册工具完成操作，再以语音回复——**新增能力只需放入一个 Markdown 文件，运行时自动生效，无需改动 C 代码与固件升级**。办公核心链路均有技能驱动，例如：

- `meeting-notes`：口述“建个会议笔记”→ 自动创建飞书文档，按日期/参会人/要点/行动项结构化写入并返回文档链接（飞书未配置时自动降级为本地笔记存储）
- `read-aloud`：将飞书文档、本地文件或网页内容清洗、分段后经 TTS 自然朗读，超长内容先摘要再分轮播报
- `task-manager`：口述待办自动追加至任务清单，说“XX 完成了”即勾选销项

其余技能覆盖天气/新闻/健康/提醒/翻译等日常助理场景，完整清单见 `agent_skills/` 目录。

### 7.3 AI 带来的实际提升

- **调试效率**：35 秒死锁问题从“现象复现”到“根因定位+修复”在 AI 辅助下 1 天内完成（传统方式预计 2-3 天）
- **文档质量**：11 份技术文档均在与 AI 讨论中迭代产出，覆盖协议设计、性能优化、踩坑记录，可直接作为团队知识库
- **代码规范性**：线程安全（原子文件同步）、错误处理（多级超时）、资源管理（缓冲区池化）均经过 AI Review
